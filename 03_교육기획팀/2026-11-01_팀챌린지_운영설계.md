## 0. 설계의 뼈대

```
 [1회차] 연습(3문항, 바로 해설) → 진단(12문항) → 평가A(8문항)
            │                     │                 │
            │            팀 편성 참고(비공개)   기준점수(비공개, 고정)
            ▼                     └──────┬──────────┘
      반 전체 익명 결과 + 규칙 안내       ▼
                                 교수가 혼합 수준 팀 편성(수준 이름 없음)
 [2·3회차]                               │
   ① 팀 연습(6문항, 상의해도 됨, 바로 해설) ◀┘
   ② 공통 평가 B / C (8문항, 혼자, 해설은 끝난 뒤)
   ③ 반 전체 해설(가장 많이 틀린 개념 2개) + 팀 회고 1분
   ④ 향상점수 0/10/20 (교수만 계산) → 팀 점수 = 평균
   ⑤ 수업 끝: 목표 달성 팀 모두 인정 (3회차는 종합 인정 + 익명 설문)
```

**재미와 배움의 연결**: 팀 연습에서 서로 설명하고(또래 설명), 평가는 혼자 보며 스스로 떠올리고(인출 연습), 끝나면 바로 해설을 봅니다(교정 피드백). 처음의 나보다 나아지면 팀에 보탬이 됩니다(성장 목표). 팀에 점수를 보태는 사람은 원래 잘하는 사람이 아니라 처음보다 나아진 사람입니다.

| 게임 요소 | 늘리려는 학습 행동 | 근거 |
|---|---|---|
| 공통 평가(혼자 풀기) | 도움 없이 떠올리기(인출 연습), 각자 자기 몫 책임지기 | 교실 퀴즈 메타분석 g=0.499(Yang 외 2021, 사실검증 ✅), 개인 책임(Slavin) |
| 팀 연습(상의 허용) | 동료에게 이유를 설명하기, 오답의 원인을 말로 정리하기 | 협동 효과(Johnson 외 1981) |
| 바로 해설 | 틀린 이유 확인, 오답을 정답으로 잘못 외우지 않기 | Butler & Roediger 2008, Butler 외 2013 (✅) |
| 향상점수(0·10·20) | 남이 아니라 처음의 나보다 나아지려는 노력 | STAD(Slavin, ✅) |
| 팀 점수 = 평균 | 팀원 모두가 배우도록 서로 돕기(팀 인원 차이 보정) | STAD |
| 목표 달성 팀 모두 인정 | 순위 다툼보다 팀 목표 달성에 집중 | 정보를 주는 칭찬은 흥미를 키움(Deci 외 1999, ✅) |
| 반 전체 오답 개념 공개 | 놓친 개념을 다시 보기(다음 회차 팀 연습에 다시 나옴) | 간격 반복(Cepeda 외 2006, ✅) |

> **넣지 않는 것**: 속도 보너스, 개인 순위, 실시간 순위표, 상품, 성적 반영, 운으로 점수가 바뀌는 요소, 결제 요소. Socrative의 **Space Race(로켓 경주)도 쓰지 않습니다.** 활동하는 동안 팀별 진행 위치가 화면에 보여서, 순위는 활동이 끝난 뒤에만 공개한다는 결재 조건과 맞지 않습니다.

  - 보고서는 30일만 남으므로 수업 당일에 내려받습니다.
  - 무료 플랜에서 Excel 보고서를 내려받을 수 있는지는 아직 확인하지 못했습니다(미확인). 안 되면 **Google 설문지 퀴즈 모드**(무료, 스프레드시트로 바로 저장)를 평가 세트에만 예비로 씁니다. 결과를 손으로 옮겨 적지는 않습니다. 옮겨 적다 실수하면 '기록 누락·중복 0건' 합격 기준을 지키기 어렵습니다.

### 1-3. 참가자 코드 카드
- 데이터 분석가가 무작위 4자리 코드를 인원보다 10장 넉넉하게 만듭니다. 헷갈리는 글자(0/O, 1/I/L)는 뺍니다(예: `K7M2`).
- 1회차에 카드를 뒤집어 놓고 각자 한 장씩 고르게 합니다. **교수님도 누가 어느 코드인지 모르는 것이 원칙**이고, 코드와 실명을 짝지은 명단은 만들지 않습니다(결재 ⑤).
- 참가자는 코드를 휴대폰 메모에 적어 둡니다. 카드를 잃어버리면 새 코드를 받습니다(3-2).
- **같은 4자리 코드를 트랙 B 웹앱에서도 씁니다**(서비스 기획자도 같은 내용으로 지시받음). 웹앱을 수업에서 시연할 때는 **점수에 쓰지 않는 연습 세트로만** 합니다. 진단·평가A·B·C는 웹앱에 올리지 않고, 웹앱 결과는 향상점수나 팀 점수에 넣지 않습니다.

## 4. 향상점수 규칙 (데이터 분석가용 계산 규칙)

### 4-1. 기본 정의

| 용어 | 계산 규칙 |
|---|---|
| 정답률 | 정답 수 ÷ 그 세트에서 유효한 문항 수 × 100. 소수 첫째 자리에서 반올림해 저장하고, 이후 계산은 저장한 값으로 합니다. |
| 기준점수 (확정: 고정) | **평가A 정답률 하나로 정하고 평가B·C 모두에 씁니다.** 회차마다 바꾸지 않습니다. 예외 ①: 진단 정답률이 평가A보다 25%p 이상 높으면 기준점수 = (진단 + 평가A) ÷ 2. 예외 ②: 평가A가 없고 진단만 있으면 진단 정답률. 예외 ③: 1회차 결석, 코드 분실, 새 참가자는 1회차 응시자 평가A 평균. |

| 경계 | 6문항일 때 | 8문항일 때 | 결정 | 이유 |
|---|---|---|---|---|
| 높은 점수 보정 80% | 6개 중 5개 | **8개 중 7개** | **유지** | 한 문제까지는 실수해도 보정을 받습니다. 90%로 올리면 8개를 다 맞혀야 해서(7/8 = 87.5%) 한 문제 실수로 보정을 놓칩니다. 75%로 내리면 8개 중 6개라 보정이 너무 넓어집니다. |
| 0점 경계 −20%p | 2문제 이상 덜 맞힘 | **2문제 이상 덜 맞힘(−25)**. 1문제 덜 맞힘(−12.5)은 '유지' | **유지** | 한 문제 실수로는 0점이 되지 않습니다. |
| 20점 경계 | +10%p (1문제 더 = +16.7) | +10%p로 두면 **1문제만 더 맞혀도(+12.5) 20점** | **+20%p로 변경** | 위아래를 똑같이 "한 문제는 유지, 두 문제부터 변화"로 맞췄습니다. 4지선다라서 한 문제는 찍어서 더 맞힐 수도 있습니다. 한 문제 운으로 점수가 10점에서 20점으로 바뀌지 않게 하려는 것입니다. |

### 4-5. 원래 STAD와 다른 점

| 항목 | 원래 STAD (Slavin) | 이번 팀 챌린지 | 바꾼 이유 |
|---|---|---|---|
| 점수 단계 | 5 / 10 / 20 / 30 (4단계) | 0 / 10 / 20 (3단계) | 단순하게 하고, 최고점을 낮춰 일부러 못 보는 이득을 줄임 |
| 구간 폭 | 기준 대비 10점 단위 | 기준 대비 ±20%p (8문항으로 2문제) | 8문항은 1문제가 12.5%p라서, 한 문제 차이로 구간이 바뀌지 않게 함 |

| 평가 문항 | 교사가 낸 단원 퀴즈 | 모두 같은 공통 평가, 연습 문항과 분리 | 수준별 문제의 정답률로는 향상을 비교할 수 없음(ChatGPT 지적 ①, 교훈노트) |
| 개인 결과 공개 | 학급 소식지에 개인 향상을 칭찬하기도 함 | 팀원끼리도 비공개 | 성인 교수자의 체면 부담 |
| 대상 | 초·중등 학생 | 성인 교수자·실무자 | 성인 대상 근거가 적어 설문으로 확인 |

출처: STAD 향상점수 표는 Slavin(1995) 재인용 자료([hrmars](https://hrmars.com/papers_submitted/3966/students-team-achievement-division.pdf), 학습과학 보고서 사실검증 25번 ✅)입니다. Slavin 원문(ERIC ED295910)은 직접 보지 못했습니다(미확인).

### 4-6. "일부러 못 보기" 방지책

### 4-7. 팀 점수·인정·순위 규칙

| 항목 | 계산 규칙 |
|---|---|
| 팀 점수(회차별) | 그 회차 집계 대상 팀원의 향상점수 평균. 소수 첫째 자리에서 반올림. 집계 대상이 0명이면 "기록 없음" |
| 성장 목표 달성 | 팀 점수 ≥ 10 (팀이 평균적으로 자기 기준을 지켰거나 넘음) |
| 성장 우수 | 팀 점수 ≥ 15 |
| 챌린지 완주 팀(3회차 종합) | 2·3회차 모두 "성장 목표 달성". 한 회차가 "기록 없음"이면 남은 1회만으로 판정 |
| 회차 순위 | 팀 점수가 높은 순서, 같은 점수는 같은 순위(1, 1, 3 방식). **성장 목표를 달성한 팀만 순위표에 나옵니다.** |
| 종합 순위(3회차) | 기록이 있는 회차의 팀 점수 평균 순서. 같은 점수는 같은 순위. 상위 3위까지만 발표 |
| 팀원 수 표시 | 팀 점수만 보여 주고, 몇 명으로 나눈 평균인지는 보여 주지 않음(비경쟁 신청자를 짐작하지 못하게) |

예: 4명 팀 20·10·10·0 → 10.0(달성) / 3명 팀 20·20·10 → 16.7(우수) / 3명 팀 10·0·10 → 6.7(순위표에 나오지 않음)

### 4-9. 비경쟁 참여 선택권
- 신청: 그 회차에 Socrative 이름 칸에 코드 뒤에 `-N`을 붙여 넣습니다(예: `K7M2-N`). 교수님 보고서에만 보이고 팀원은 모릅니다. 회차마다 바꿀 수 있습니다.
- 비경쟁 참여자도 팀 자리에서 연습하고 평가를 풀고 해설을 봅니다. 다만 향상점수가 팀 점수에 들어가지 않습니다. 기준점수는 고정이라, 경쟁으로 돌아와도 같은 기준이 적용됩니다.
- 팀원이 모두 비경쟁이면 그 팀은 "기록 없음"입니다.

### 4-10. 시범 전에 공개·고정할 규칙 문구 (1회차 안내문 그대로)

> **AI Agent 실무역량 팀 챌린지 — 참여 안내 (2026년 2학기 시범 운영 규칙, 시범 기간 중 변경 없음)**
>
> 1. 이 활동은 **성적에 반영되지 않습니다.** 결과는 수업 개선에만 쓰고, 학기가 끝나면 지웁니다.
> 2. 실명·학번·연락처는 받지 않습니다. **입장 링크(또는 QR코드)로 들어와 이름 칸에 무작위 참가자 코드**만 넣습니다. 교수자도 누가 어느 코드인지 모릅니다.
> 3. 모두 3회입니다. 1회차는 혼자 연습하고 점검과 평가A를 보며, 팀 활동은 없습니다. 2·3회차는 교수자가 짠 3~4명 팀으로 합니다. 모든 팀에 여러 수준이 고르게 섞이게 짭니다.
> 4. 팀 점수는 처음 실력이 아니라 **각자 자기 기준보다 얼마나 나아졌는지**로 정합니다. 모두 같은 공통 평가(8문항)를 풀고, 연습 문항은 점수에 들어가지 않습니다.
> 5. 개인 향상점수: 이번 평가에서 8문항 중 7개 이상 맞히면 기준과 관계없이 20점, 자기 기준보다 20%p 이상 오르면 20점, 기준에서 ±20%p 안이면 10점, 20%p 넘게 내려가면 0점입니다. 기준은 1회차 평가A 결과이고 2·3회차 내내 같습니다. (1회차 점검이 평가A보다 25%p 이상 높으면 두 값의 평균을 기준으로 합니다. 1회차에 빠지면 1회차 참여자 평균을 기준으로 합니다.)
> 6. 팀 점수는 팀원 향상점수의 **평균**입니다. 10점 이상이면 '성장 목표 달성', 15점 이상이면 '성장 우수'이고, **조건을 넘은 팀은 모두 인정합니다.**
> 7. 빨리 답한다고 점수가 더 붙지 않습니다. 순위는 활동이 끝난 뒤에만, 목표를 달성한 팀만 발표합니다.
> 8. **개인 점수는 본인 외에 아무에게도 공개하지 않습니다.** 팀원에게 점수를 묻지 않는 것이 팀 규칙입니다.
> 9. 경쟁이 부담스러우면 이름 칸에 코드 뒤 `-N`을 붙여 **비경쟁으로 참여**할 수 있습니다. 팀 활동은 똑같이 하고 점수만 팀에 들어가지 않으며, 팀원은 이 사실을 알 수 없습니다.
> 10. 결석해도 불이익은 없습니다. 팀 점수는 그날 참여한 팀원만으로 계산합니다.

| 낮은 수준으로 분류됐다는 느낌 | 수준 이름을 쓰지 않음, 팀 번호 무작위, 코드는 가나다순, 진단은 "위치 점검"으로 소개 |
| 팀에 피해를 준다는 압박 | 평균 점수, ±1문제는 '유지', 결석 불이익 없음, 비경쟁 신청은 팀원이 모름 |
| 손이 빠른 사람이 유리함 | 속도 보너스 없음, Space Race 안 씀, 평가 시간 넉넉하게(문항당 약 50초) |
| 첫날부터 평가받는 느낌 | 1회차에는 팀 대결 없음, 몸풀기 연습부터 시작 |
| 성적 걱정 | 매 회차 첫 문장에서 성적에 넣지 않는다고 말함 |
| 꼴찌 팀 낙인 | 미달 팀은 부르지 않음, 순위표에는 달성 팀만 |
| 신원 노출 | 무작위 코드, 교수도 코드와 사람을 짝짓지 않음, 외부 AI에 보내지 않음, 학기 끝나면 삭제 |

## 6. "유치하지 않은" 톤 가이드

| 쓰는 말 | 쓰지 않는 말 | 이유 |
|---|---|---|
| 팀 챌린지, 공통 평가, 위치 점검 | 게임, 배틀, 시험 | 실무 연수의 느낌 |
| 성장 목표 달성, 성장 우수, 챌린지 완주 | 레벨업, 승리, MVP, 꼴찌, 패배 | 남과의 비교가 아니라 자기 성장 중심 |
| 기준점수, 향상점수 | 레벨, 등급, 상·중·하, 초급 | 수준 이름은 공개하지 않는 원칙 |
| "실무에서 흔한 착각입니다" | "많이들 틀리셨네요" | 사람이 아니라 개념을 짚음 |
| "왜 그럴듯해 보였을까요?" | "누가 틀렸나요?" | 되돌아보는 질문을 개념 중심으로 |

- **화면**: 흰 배경에 표와 막대그래프 하나만 둡니다. 캐릭터, 폭죽, 효과음, 카운트다운 음악은 쓰지 않고, 남은 시간은 숫자로만 보여 줍니다. 입장 링크와 QR코드는 크게 띄웁니다.
- **말투**: 연수 진행자처럼 차분한 존댓말로 합니다. 과장된 칭찬 대신 구체적인 정보로 칭찬합니다.
- **연결 짓기**: 매 회차 끝에 "이 방식은 선생님들 수업에도 그대로 쓰실 수 있습니다"라는 한 문장을 넣습니다.

## 7. 참가자 한 명의 흐름 (예: 코드 K7M2)
1. 1회차: QR코드로 들어와 이름 칸에 `K7M2`를 넣습니다. 연습 3문항으로 도구를 익히고, 진단 12문항과 평가A 8문항을 봅니다. 평가A는 4/8(50%)이고, 이 점수가 기준점수가 됩니다. 아무에게도 공개되지 않습니다.
2. 2회차: 화면에서 자기 코드를 찾아 3팀에 앉습니다. 팀 연습에서 링크 문항을 팀원에게 설명하고, 평가B에서 5/8(62.5%)을 받습니다. 한 문제를 더 맞힌 것이라 '유지'로 10점입니다(교수님만 앎). 수업 끝에 "3팀 성장 목표 달성"이 발표됩니다.
3. 3회차: 기준은 그대로 50%입니다. 평가C에서 7/8을 받아 20점입니다(80% 이상 보정). 팀 점수는 15.0으로 '성장 우수'이고, 두 번 모두 달성해 '챌린지 완주'입니다. 마지막에 익명 설문에 답합니다.

## 8. 예상 부작용과 대책

| 부작용 | 대책 | 확인 방법 |
|---|---|---|
| 평가 세트끼리 난이도가 달라 한 회차에 전체 점수가 오르내림 | 세트별 반 평균을 함께 보고. 규칙은 중간에 바꾸지 않음 | 분석가가 세트별 반 평균 비교 |
| 평가 문항이 퍼짐 | 문제지를 배포하지 않음, 연습과 겹치지 않음, 문항 순서 섞기(보기는 섞지 않음) | 정답률이 갑자기 오르는지 봄 |
| 팀 연습에서 한 사람이 다 풀어 줌 | 평가는 반드시 혼자, "이유를 한 문장으로" 규칙 | 교수님이 돌아다니며 관찰 |
| 대부분의 팀이 달성해 인정의 의미가 약해짐 | 2단계(달성/우수)로 운영. 기준 조정은 겨울방학 개정 때 | 회차별 달성 팀 비율 |
| ±20%p로 넓혀서 20점이 드물어짐 | 7/8 이상이면 받는 보정, 15점 '성장 우수'로 팀 수준에서 구분 | 회차별 20점 비율 |
| 0점을 받은 사람이 의욕을 잃음 | 2문제 넘게 내려갈 때만 0점이고 비공개. 기준이 고정이라 다음 회차로 넘어가지 않음 | 설문 Q3·Q5 |
| 링크·QR 입장 실패, 와이파이 끊김, 중복 접속 | 방 이름을 이용한 예비 입장, 첫 제출만 인정, 시간 여유, 예비 도구(Google 설문지) | 2주차 예비 실험 |
| 1회차가 20문항 이상이라 시간이 빠듯함 | 마무리 해설은 2회차로 미룰 수 있음. 진단·평가A는 줄이지 않음 | 예비 실험에서 시간 재기 |

## 9. 확인이 남은 것 (결재2 전)
1. Socrative: 입장 링크·QR이 실제로 열리는지, 방 이름, 무료 Excel 내려받기 가능 여부, 한 방에서 한 활동만 열리는지 (1주차 계정 테스트). 퀴즈를 지워도 보고서가 남는지(미확인)는 2주차 예비 실험에서 확인합니다. 지우기 전에는 반드시 Excel을 내려받습니다.
2. `quiz_sets.json` 세트 제목의 회차 표기 → **해결됨(2026-11-01)**
3. 엑셀 기본값을 4-11의 ⓐ~ⓘ에 맞게 고치기 (데이터 분석가)
4. 1회차 20분 안에 진단과 평가A를 다 볼 수 있는지, 결과 계산과 발표가 수업 끝 3분 안에 되는지 (2주차 예비 실험 5~10명). 늦어지면 결과 발표를 다음 회차 시작으로 옮깁니다.
