## 0. 설계의 뼈대

```
 [1회차] 연습(3문항, 종이, 바로 해설) → 진단(12문항) → 평가A(8문항)
            │                          │                 │
            │                 팀 편성 참고(비공개)   기준점수(비공개, 고정)
            ▼                          └──────┬──────────┘
      반 전체 익명 결과 + 규칙 안내            ▼
                                 교수가 혼합 수준 팀 편성(수준 이름 없음)
 [2·3회차]                                    │
   ① 팀 연습(6문항, 종이 연습지, 상의해도 됨, 문항마다 해설) ◀┘
   ② 공통 평가 B / C (8문항, Socrative, 혼자, 같은 시각 시작·종료)
   ③ 반 전체 해설(가장 많이 틀린 개념 2개) + 팀 회고 1분
   ④ 개인 0/10/20점 (교수만 계산) → 팀 점수 = 평균
   ⑤ 수업 끝: 15점 이상 "학습목표 달성" 팀 모두 인정 (3회차는 종합 인정 + 익명 설문)
```

**재미와 배움의 연결**: 팀 연습에서 서로 설명하고(또래 설명), 평가는 혼자 보며 스스로 떠올리고(인출 연습), 끝나면 해설을 봅니다(교정 피드백). 개념을 숙달하거나 처음의 나보다 나아지면 팀에 보탬이 됩니다. 팀에 점수를 보태는 사람은 원래 잘하는 사람만이 아니라 처음보다 나아진 사람이기도 합니다.

| 게임 요소 | 늘리려는 학습 행동 | 근거 |
|---|---|---|
| 공통 평가(혼자 풀기) | 도움 없이 떠올리기(인출 연습), 각자 자기 몫 책임지기 | 교실 퀴즈 메타분석 g=0.499(Yang 외 2021, 사실검증 ✅), 개인 책임(Slavin) |
| 팀 연습(상의 허용, 종이 연습지) | 동료에게 이유를 설명하기, 오답의 원인을 말로 정리하기 | 협동 효과(Johnson 외 1981) |
| 문항마다 해설 | 틀린 이유 확인, 오답을 정답으로 잘못 외우지 않기 | Butler & Roediger 2008, Butler 외 2013 (✅) |
| 개인 점수(0·10·20, "숙달 또는 향상"·"유지") | 남이 아니라 처음의 나보다 나아지거나 개념을 확실히 익히려는 노력 | STAD(Slavin, ✅)를 고쳐 씀(4-5) |
| 팀 점수 = 평균, 15점 이상 달성 | 팀원 모두가 배우도록 서로 돕기(팀 인원 차이 보정) | STAD |
| 학습목표 달성 팀 모두 인정 | 순위 다툼보다 팀 목표 달성에 집중 | 정보를 주는 칭찬은 흥미를 키움(Deci 외 1999, ✅) |
| 반 전체 오답 개념 공개 | 놓친 개념을 다시 보기(다음 회차 팀 연습에 다시 나옴) | 간격 반복(Cepeda 외 2006, ✅) |

> **넣지 않는 것**: 속도 보너스, 개인 순위, 실시간 순위표, 상품, 성적 반영, 무작위 보너스처럼 운으로 점수를 주는 장치, 결제 요소. Socrative의 **Space Race(로켓 경주)도 쓰지 않습니다.** 활동하는 동안 팀별 진행 위치가 화면에 보여서, 순위는 활동이 끝난 뒤에만 공개한다는 결재 조건과 맞지 않습니다. (4지선다 평가 자체에 들어 있는 찍기 운은 없앨 수 없으므로 4-12절에 해석 주의로 적습니다.)

  - 링크와 QR코드는 수업 슬라이드와 안내문에만 넣습니다. SNS나 공개 게시판에는 올리지 않습니다(외부 공개 금지 원칙).
- 활동 설정 (진단·평가A·B·C 모두 같음. 메뉴 이름과 무료 플랜에서 되는지는 1주차 계정 테스트에서 확인 필요):

- **먼저 끝난 분 안내**: "다 푸신 분은 휴대폰을 엎어 두시고, 종료 시각까지 대화는 삼가 주세요. 연습지를 다시 보셔도 됩니다." 성적에 들어가지 않는 성인 수업이므로 완벽하게 막기보다 이렇게 줄이고, 남는 한계는 4-12에 적습니다.

  - **저장 퀴즈는 진단·평가A·B·C 4개만 처음부터 올려 둡니다.** 한도 5개 안이라 학기 중에 지우거나 바꿔 올릴 일이 없습니다. 남는 1칸은 비워 둡니다.

  - 무료 플랜에서 Excel 보고서를 내려받을 수 있는지는 아직 확인하지 못했습니다(미확인). 안 되면 **Google 설문지 퀴즈 모드**(무료, 스프레드시트로 바로 저장)를 평가 세트에만 예비로 씁니다. 이때도 문제·보기 섞기, 점수 숨기기, 한 번만 응답을 같게 켭니다. 결과를 손으로 옮겨 적지는 않습니다. 옮겨 적다 실수하면 '기록 누락·중복 0건' 합격 기준을 지키기 어렵습니다.

### 1-4. 참가자 코드 카드
- 데이터 분석가가 무작위 **6자리 코드**(영문 대문자+숫자, 헷갈리는 0/O, 1/I/L은 뺌, 예: `K7M2PX`)를 인원보다 10장 넉넉하게 만들고, 인쇄한 코드 전체 목록을 엑셀 명단 시트에 넣습니다.
- 1회차에 카드를 뒤집어 놓고 각자 한 장씩 고르게 합니다. **교수님도 누가 어느 코드인지 모르는 것이 원칙**이고, 코드와 실명을 짝지은 명단은 만들지 않습니다(결재 ⑤).
- **현장 대조**: 카드를 나눠 준 뒤 남은 카드를 모아 두면, 실제로 나간 코드 목록을 알 수 있습니다(누가 가졌는지는 모름). 평가 시작 전에 Socrative 입장 인원이 출석 인원과 맞는지 세어 보고, 회차가 끝난 뒤 보고서의 코드가 나간 코드 목록에 있는지 데이터 분석가가 대조합니다. 목록에 없는 코드는 3-2대로 처리합니다.
- 참가자는 코드를 휴대폰 메모에 적어 둡니다. 카드를 잃어버리면 새 코드를 받습니다(3-2).
- **트랙 B 연습용 웹앱(결재3 승인 시)에서도 같은 코드를 화면에 넣을 수 있지만, 웹앱은 코드를 기록하거나 맞는지 검사하지 않습니다(화면 표시용).** 웹앱은 점수에 쓰지 않는 연습 세트만 다룹니다. 진단·평가A·B·C는 웹앱에 올리지 않고, 웹앱 결과는 개인 점수나 팀 점수에 넣지 않습니다.

## 3. 팀 편성 규칙 (교수님용, 수준 이름은 쓰지 않음)

### 3-1. 짜는 순서 (지그재그 배분)

| 단계 | 방법 |
|---|---|
| ① 팀 수 | 참여 인원 ÷ 4를 올림합니다(20명 → 5팀, 33명 → 9팀, 50명 → 13팀). 이렇게 하면 모든 팀이 3명 또는 4명이 됩니다. |
| ② 줄 세우기 | **진단 12 + 평가A 8 = 20문항의 합산 정답률**이 높은 순서로 코드를 줄 세웁니다. 문항이 많을수록 한 문제로 생기는 우연한 차이가 줄어듭니다. (팀 편성에만 쓰고, 기준점수에는 쓰지 않습니다.) 평가A만 없으면 진단 정답률로 줄에 넣고, 동점이면 무작위로 정하고, 1회차 결석자는 맨 끝에 둡니다. |

## 4. 개인 점수 규칙 (데이터 분석가용 계산 규칙)

### 4-1. 기본 정의

| 용어 | 계산 규칙 |
|---|---|
| 정답률 | 정답 수 ÷ 그 세트에서 유효한 문항 수 × 100. 소수 첫째 자리에서 반올림해 저장하고, 이후 계산은 저장한 값으로 합니다. |
| 원점수 | 세트별 정답 수(예: 5/8). 정답률과 함께 A·B·C 모두 기록합니다(4-12). |
| 기준점수 (확정: 고정) | **평가A 정답률 하나로 정하고 평가B·C 모두에 씁니다.** 회차마다 바꾸지 않고, 진단 점수로 고치거나 섞지 않습니다. 예외: 평가A가 없으면(결석·지각·새 참가자·코드 분실) **그 사람의 첫 응시 정답률**이 기준점수가 되고, 그 회차 판정은 "보류"입니다. |
| 교수 확인 표시 | 진단 정답률 − 평가A 정답률 ≥ 30%p이면 엑셀에 "확인" 표시만 합니다(임시값). **점수는 바뀌지 않습니다.** 일부러 평가A를 낮게 봤을 가능성을 교수님이 알고 결과를 해석할 때 참고하기 위한 것입니다. |
| 집계 대상 | 그 회차에 정상 응시했고, 비경쟁을 신청하지 않았고, 나간 코드 목록에 있고, "보류"가 아닌 참가자 |

### 4-2. 개인 점수 표 (평가B·C마다)

| 순서 | 조건 (위에서부터 먼저 맞는 것 하나만 적용) | 점수 | 이름 | 기록 구분 |
|---|---|---|---|---|
| 0 | 기준점수가 없음(평가A 결석 등) | — | 보류 | "보류". 이번 정답률을 기준점수로 저장, 팀 평균에서 뺌 |
| 1 | **이번 평가 정답률** ≥ 80% (8문항 중 7개 이상) | **20** | **숙달 또는 향상** | **"숙달"** (기준점수와 관계없이 이번 정답률만 봄) |
| 2 | 이번 정답률 ≥ 기준점수 + 20 | **20** | **숙달 또는 향상** | **"향상"** (8문항 기준 2문제 이상 더 맞힘) |
| 3 | 기준점수 − 20 ≤ 이번 정답률 < 기준점수 + 20 | **10** | **유지** | "유지" (한 문제 더 맞히거나 덜 맞힌 정도) |
| 4 | 이번 정답률 < 기준점수 − 20 | **0** | **보완 필요** | "보완 필요" (**교수님만 보는 값**) |

- 참가자에게 알리는 이름은 "숙달 또는 향상"·"유지"뿐이고, 그것도 개인에게 따로 알려 주지 않습니다. "숙달"과 "향상"의 구분은 엑셀에만 남겨 분석에 씁니다(20점이 어느 쪽에서 나왔는지 알아야 해석할 수 있음).

### 4-3. 8문항 기준으로 경계값을 다시 점검한 결과

8문항에서는 1문제가 12.5%p입니다. 기준점수도 같은 8문항(평가A)이라, 보통은 차이가 12.5%p 단위로 납니다(0, ±12.5, ±25, ±37.5 …).

| 경계 | 6문항일 때 | 8문항일 때 | 결정 | 이유 |
|---|---|---|---|---|
| 숙달 80% | 6개 중 5개 | **8개 중 7개** | **유지** | 한 문제까지는 실수해도 숙달로 봅니다. 90%로 올리면 8개를 다 맞혀야 해서(7/8 = 87.5%) 한 문제 실수로 놓칩니다. 75%로 내리면 8개 중 6개라 너무 넓어집니다. |
| 0점 경계 −20%p | 2문제 이상 덜 맞힘 | **2문제 이상 덜 맞힘(−25)**. 1문제 덜 맞힘(−12.5)은 '유지' | **유지** | 한 문제 실수로는 0점이 되지 않습니다. |
| 향상 경계 | +10%p (1문제 더 = +16.7) | +10%p로 두면 **1문제만 더 맞혀도(+12.5) 20점** | **+20%p로 변경** | 위아래를 똑같이 "한 문제는 유지, 두 문제부터 변화"로 맞췄습니다. 4지선다라서 한 문제는 찍어서 더 맞힐 수도 있습니다. 한 문제 운으로 10점이 20점으로 바뀌지 않게 하려는 것입니다(그래도 남는 찍기 운은 4-12). |

### 4-7. 팀 점수·인정·순위 규칙

  - 8문항이라 1문제가 12.5%p입니다. 한두 문제 차이는 우연일 수 있습니다.
  - 평가A·B·C의 난이도가 같은지 확인하지 않았습니다. 한 회차에 반 전체 점수가 함께 오르내리면 사람이 아니라 세트 차이일 수 있습니다.
  - **찍기 운**: 모두가 아무렇게나 찍는다고 가정해도 평가B에서 20점("향상")을 받을 확률이 약 19%, B·C 중 한 번 이상 받을 확률이 약 31%입니다(ChatGPT 계산을 비서실장이 이항분포로 다시 계산해 확인: 19.1%·30.9%, 4지선다 8문항·기준 A도 무작위라는 가정). 20점 하나만으로 성장했다고 보지 않습니다.
  - 0/8에서 0/8로 그대로여도 10점 "유지"입니다. "유지"는 나아졌다는 뜻이 아닙니다.
  - 기준을 평가A로 고정했기 때문에, 누군가 평가A를 일부러 낮게 보면 그 효과가 두 회차 내내 남습니다("확인" 표시로만 살핍니다).
  - 문제·보기 섞기와 같은 시간창으로도 먼저 끝난 사람의 답 전달을 완전히 막지는 못합니다.

## 5. 부담을 줄이는 장치

| 부담 | 장치 |
|---|---|
| 동료 교수 앞에서 틀리는 모습 | 개인 점수는 팀원끼리도 비공개. 최종 점수 화면 숨김. 실시간 결과 화면을 띄우지 않고, 문항별 반 정답률만 보여 줌 |
| 낮은 수준으로 분류됐다는 느낌 | 수준 이름을 쓰지 않음, 팀 번호 무작위, 코드는 가나다순, 진단은 "위치 점검"으로 소개 |
| 팀에 피해를 준다는 압박 | 평균 점수, ±1문제는 '유지', 0점 이름 "보완 필요"는 교수만 봄, 결석 불이익 없음, 비경쟁 신청은 팀원이 모름 |
| 손이 빠른 사람이 유리함 | 속도 보너스 없음, Space Race 안 씀, 평가 시간 넉넉하게(문항당 약 50초), 모두 같은 종료 시각 |
| 첫날부터 평가받는 느낌 | 1회차에는 팀 대결 없음, 종이 연습지 몸풀기부터 시작 |
| 성적 걱정 | 매 회차 첫 문장에서 성적에 넣지 않는다고 말함 |
| 꼴찌 팀 낙인 | "도전 중" 팀은 부르지 않음, 순위표에는 학습목표 달성 팀만 |
| 신원 노출 | 무작위 6자리 코드, 교수도 코드와 사람을 짝짓지 않음, 외부 AI에 보내지 않음, 학기 끝나면 삭제 |

## 6. "유치하지 않은" 톤 가이드

| 쓰는 말 | 쓰지 않는 말 | 이유 |
|---|---|---|
| 팀 챌린지, 공통 평가, 위치 점검 | 게임, 배틀, 시험 | 실무 연수의 느낌 |
| 학습목표 달성, 도전 중, 챌린지 완주 | 레벨업, 승리, MVP, 꼴찌, 패배, 실패 | 남과의 비교가 아니라 자기 학습 중심 |
| 기준점수, 숙달 또는 향상, 유지 | 레벨, 등급, 상·중·하, 초급 | 수준 이름은 공개하지 않는 원칙 |
| (교수용 기록에만) 보완 필요 | 낙제, 하락, 0점 | 참가자에게는 쓰지 않음 |
| "실무에서 흔한 착각입니다" | "많이들 틀리셨네요" | 사람이 아니라 개념을 짚음 |
| "왜 그럴듯해 보였을까요?" | "누가 틀렸나요?" | 되돌아보는 질문을 개념 중심으로 |

- **화면**: 흰 배경에 표와 막대그래프 하나만 둡니다. 캐릭터, 폭죽, 효과음, 카운트다운 음악은 쓰지 않고, 남은 시간은 숫자로만 보여 줍니다. 입장 링크와 QR코드는 크게 띄웁니다.
- **말투**: 연수 진행자처럼 차분한 존댓말로 합니다. 과장된 칭찬 대신 구체적인 정보로 칭찬합니다.
- **연결 짓기**: 매 회차 끝에 "이 방식은 선생님들 수업에도 그대로 쓰실 수 있습니다"라는 한 문장을 넣습니다.

## 7. 참가자 한 명의 흐름 (예: 코드 K7M2PX)
1. 1회차: QR코드로 들어와 이름 칸에 `K7M2PX`를 넣습니다. 종이 연습지 3문항으로 몸을 풀고, 휴대폰으로 진단 12문항과 평가A 8문항을 모두와 같은 시각에 시작해 봅니다. 평가A는 4/8(50%)이고, 이 점수가 기준점수가 됩니다. 아무에게도 공개되지 않습니다.
2. 2회차: 화면에서 자기 코드를 찾아 3팀에 앉습니다. 팀 연습지의 링크 문항을 팀원에게 설명하고, 평가B에서 5/8(62.5%)을 받습니다. 한 문제를 더 맞힌 것이라 10점 "유지"입니다(교수님만 앎). 3팀 평균은 12.5점이라 "도전 중"이고, 팀 번호는 불리지 않습니다. 교수님이 "모든 팀이 다시 도전할 수 있습니다"라고 말합니다.
3. 3회차: 기준은 그대로 50%입니다. 팀 연습에서 지난 오답 개념을 다시 짚고, 평가C에서 7/8을 받아 20점 "숙달 또는 향상"(기록은 "숙달")입니다. 3팀 평균은 17.5점으로 "학습목표 달성"입니다. 두 번 모두 달성하지는 못해 '챌린지 완주'는 아닙니다. 마지막에 익명 설문에 답합니다. 엑셀에는 이 사람의 원점수 4→5→7이 함께 남습니다.

## 8. 예상 부작용과 대책

| 부작용 | 대책 | 확인 방법 |
|---|---|---|
| 평가 세트끼리 난이도가 달라 한 회차에 전체 점수가 오르내림 | 세트별 반 평균과 원점수를 함께 보고. 규칙은 중간에 바꾸지 않음 | 분석가가 세트별 반 평균 비교 |
| 평가 문항·답이 퍼짐 | 문제지를 배포하지 않음, 연습과 겹치지 않음, 문제·보기 순서 섞기, 같은 시작·종료 시각, 최종 점수 숨김, 먼저 끝난 분 대화 자제 | 정답률이 갑자기 오르는지 봄 |
| 팀 연습에서 한 사람이 다 풀어 줌 | 평가는 반드시 혼자, "이유를 한 문장으로" 규칙 | 교수님이 돌아다니며 관찰 |
| 15점 기준이 높아 "도전 중" 팀이 많아짐 | 도전 중 팀은 부르지 않음, 반 전체 개념 향상을 함께 인정, 기준은 다음 회차로 넘어가지 않음. 기준 조정은 겨울방학 개정 때 | 회차별 달성 팀 비율, 설문 Q3·Q5 |
| 찍기 운으로 20점이 나와 성장으로 잘못 해석됨 | "숙달/향상" 구분 기록, 원점수 변화 함께 보기, 탐색적 파일럿으로만 보고(4-12) | 분석가 보고서의 해석 주의 문단 |
| 0점을 받은 사람이 의욕을 잃음 | 2문제 넘게 내려갈 때만 0점이고 "보완 필요"라는 이름도 교수만 봄. 기준이 고정이라 다음 회차로 넘어가지 않음 | 설문 Q3·Q5 |
| 평가A를 빠지거나 일부러 낮게 봄 | 결석 시 첫 응시가 기준·그 회차 보류(이득 없음), 진단과 차이가 크면 "확인" 표시 | "확인"·"보류" 인원 수 |
| 링크·QR 입장 실패, 와이파이 끊김, 코드 오타 | 방 이름을 이용한 예비 입장, 6자리 코드 카드 그대로 입력 안내, 입장 인원과 나간 코드 대조, 첫 제출만 인정, 예비 도구(Google 설문지) | 2주차 예비 실험 |
| 1회차가 20문항 이상이라 시간이 빠듯함 | 마무리 해설은 2회차로 미룰 수 있음. 진단·평가A는 줄이지 않음 | 예비 실험에서 시간 재기 |
| 종이 연습지 준비 부담 | 회차별 1장, 문제만 인쇄(해설은 슬라이드). 결재3 승인 시 웹앱으로 대체 가능 | 예비 실험에서 확인 |

## 9. 확인이 남은 것 (결재2 전)
1. Socrative(1주차 계정 테스트): 입장 링크·QR이 실제로 열리는지, 방 이름, 무료 Excel 내려받기 가능 여부, 한 방에서 한 활동만 열리는지, **무료 플랜에서 문제 섞기·보기 섞기·최종 점수 숨기기·한 번만 응시 설정이 되는지와 메뉴 이름**(미확인). 안 되는 설정이 있으면 Google 설문지 퀴즈 모드를 평가에 씁니다.
2. `quiz_sets.json` 세트 제목의 회차 표기 → **해결됨(2026-11-01)**
3. 엑셀을 4-11의 ⓐ~ⓖ에 맞게 고치기 (데이터 분석가). 6자리 코드 카드 인쇄용 목록 만들기
4. 연습 31문항의 종이 연습지(회차별 1장)와 해설 슬라이드 만들기 (커리큘럼 설계자)
5. 1회차 20분 안에 진단과 평가A를 다 볼 수 있는지, 결과 계산과 발표가 수업 끝 3분 안에 되는지 (2주차 예비 실험 5~10명). 늦어지면 결과 발표를 다음 회차 시작으로 옮깁니다.
6. ✅ 찍기 운 확률 확인 완료(비서실장 계산 19.1%·30.9%, 2026-11-02)
