## 1. 무엇이 문제인가 (쉬운 설명)

앱은 "맞힐 확률(P)이 75~90%인 문제"를 골라 줍니다. 그런데 P에는 **찍어서 맞히는 몫**이 들어 있습니다.

- 4지선다: 아무것도 몰라도 25%는 맞힘
- O/X: 아무것도 몰라도 **50%는 맞힘**

그래서 아주 어려워하는 학생에게는 **"전혀 모르는 O/X"(P 52%)가 "조금은 아는 쉬운 4지선다"(P 45%)보다 쉬워 보이는** 착시가 생깁니다. 실제로 찍기를 뺀 "진짜 이해도"는 O/X 쪽이 5%, 쉬운 4지선다 쪽이 27%입니다. 앱은 정반대로 고르고 있었습니다.

같은 착시가 보통 학생(θ 0)·잘하는 편 학생(θ 1)에게도 생깁니다. 보통 난이도 O/X는 진짜 이해도가 50%인데도 P가 75%로 계산돼 구간 안에 들어오고, 그 결과 한 판의 37~54%가 O/X로 채워집니다.

### 문항 은행 실제 분포 (연습 106개, 직접 셈)

| 종류 | 난이도 0 (b −2) | 난이도 1 (b −1) | 난이도 2 (b 0) | 난이도 3 (b +1) | 합계 |
|---|---|---|---|---|---|
| 4지선다 | 30 | 27 | 13 | 20 | 90 |
| O/X | 0 | 1 (L08-Q4) | 15 | 0 | 16 |

- O/X는 **거의 다 난이도 2**이고 난이도 0인 O/X는 없습니다. 그래서 "어려워하는 학생 = O/X만" 문제가 생겼습니다.
- 서버 기본값처럼 15강까지만 열려 있으면: 4지선다 0/1/2/3 = 15/12/6/7, O/X 1(난이도 1) + 5(난이도 2).

### 학생 실력(θ)별 각 묶음의 P (지금 공식)

| θ | 4지 난이도0 | 4지 1 | 4지 2 | 4지 3 | O/X 1 | O/X 2 |
|---|---|---|---|---|---|---|
| −3 | 0.452 | 0.339 | 0.286 | 0.263 | **0.560** | **0.524** |
| −2 | 0.625 | 0.452 | 0.339 | 0.286 | **0.634** | 0.560 |
| −1 | **0.798** | 0.625 | 0.452 | 0.339 | **0.750** | 0.634 |
| 0 | 0.911 | **0.798** | 0.625 | 0.452 | **0.866** | **0.750** |
| 1 | 0.964 | 0.911 | **0.798** | 0.625 | 0.940 | **0.866** |
| 2 | 0.987 | 0.964 | 0.911 | **0.798** | 0.976 | 0.940 |

굵은 글씨 = 지금 규칙에서 뽑히는 묶음(75~90% 구간 안, 또는 구간이 비었을 때 0.82에 가장 가까운 것).
θ 0에서 O/X 난이도 2가 정확히 0.750으로 구간 경계에 걸리는 것도 위험합니다(소수점 하나 차이로 들어왔다 나갔다 함).

## 2. 해결안 비교

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **현재** | P = c + (1−c)/(1+e^−(θ−b)), c = 1÷보기 수로 고름 | — | 어려운 학생 O/X만, 보통 학생도 37~54% O/X |
| **A. 한 판 O/X 상한 1개** | 이번 판에 이미 O/X 1개를 냈으면 O/X 빼고 고름 | 아주 단순 | 원인(착시)은 그대로 → 어려운 학생은 여전히 판마다 **첫 문제가 전혀 모르는 O/X**. 잘하는 편 학생은 맞는 4지선다가 모자라 구간 밖 문제로 밀림 |
| **B. O/X 연속 금지** | 바로 전 문제가 O/X면 이번엔 O/X 빼고 고름 | 단순 | 어려운 학생 50~60%가 여전히 O/X. 서버에 "바로 전 문제 종류"를 새로 보내야 함 |
| **C. 고르기용 P는 c = 0.25로 통일** | 문제를 **고를 때만** 모든 문항을 4지선다처럼 c = 0.25로 계산. θ를 고치는 계산(Elo)·진단 채점은 지금처럼 진짜 c(O/X 0.5) | 착시의 **원인을 없앰**. 고르는 기준이 "진짜 이해도 67~87%"로 모든 종류에 같아짐. 숫자 하나만 바뀜 | 잘하는 편(θ 1)은 은행에 난이도 2 O/X가 많아서 여전히 54% O/X |
| **추천 = C + 한 판 O/X 최대 2개** | C에 "이번 판에 이미 O/X 2개를 냈으면, O/X 아닌 후보가 있을 때 O/X 빼기"를 더함 | C의 장점 + 어느 학생도 한 판 O/X 40%를 넘지 않음. 서버는 이미 받는 `p_exclude`만으로 셀 수 있어 **화면→서버 주고받는 값이 안 바뀜** | 규칙 1줄 추가 |

> C는 "O/X만 따로 구간을 0.833~0.933으로 올리기"와 계산상 완전히 같습니다(0.5 + 0.5 × 이해도 0.667~0.867). 숫자 하나로 끝나는 C 쪽이 실수할 곳이 적어 C로 적었습니다.

## 3. 시뮬레이션 결과

### 계산 방법 (솔직한 안내)
- 이 작업 환경에는 프로그램 실행 도구가 없어서 **파이썬을 직접 돌리지 못했습니다.** 대신 위 표처럼 문항 106개를 6묶음(종류 × 난이도)으로 정확히 세고, 앱과 같은 공식으로 **기대값을 직접 계산**했습니다. 문항이 묶음 안에서는 P가 모두 같아서, 무작위 뽑기를 수천 번 돌린 평균과 같은 값이 나옵니다.
- 같은 결과를 확인하는 파이썬 코드를 부록에 넣었습니다(개발자·QA가 1분이면 돌려 볼 수 있음). `약`이 붙은 칸은 한 판 상한이 걸려 무작위 뽑기 순서에 따라 조금 달라지는 근사값입니다(±2%p 정도).
- 조건: 30강 모두 열림, θ는 고정(학생 실력이 변하지 않는다고 가정), 하루 5문제 × 4일 = 20문제, 7일 안에 푼 문제는 다시 안 나옴. E4(2연속 오답)·E5(같은 강 3연속)는 답 결과에 따라 달라져서 뺐습니다. E4는 "P가 가장 높은 문제"를 고르므로, **현재 규칙에서는 어려운 학생에게 O/X를 더 부르고**, 추천안에서는 "가장 쉬운 4지선다"를 부릅니다.

### 결과 읽기
1. **θ −3 학생**: 평균 P는 0.53 → 0.45로 **숫자상 내려가지만**, 이건 "찍어서 맞힐 몫"이 빠졌기 때문입니다. 진짜 이해도는 0.06 → 0.27로 **4배 이상 올라갑니다**. 맞힌 것이 운이 아니라 실력이 되고, 해설·힌트에서 배울 것도 생깁니다.
2. **θ 0 학생(보통)**: O/X 37% → 4%. 평균 P는 오히려 0.78 → 0.80으로 목표(0.82)에 더 가까워집니다.
3. **θ 1 학생**: C만으로는 안 줄어듭니다(난이도 2 O/X가 15개나 되는 은행 구성 때문). 그래서 "한 판 최대 2개"를 더했습니다. 이 학생에게 나오는 O/X는 진짜 이해도가 4지선다와 같아서(0.73) 난이도는 맞고, 상한은 "문제 종류가 한쪽으로 쏠리지 않게" 하는 안전장치입니다.
4. **A(상한 1개)는 왜 아닌가**: 어려운 학생은 매일 첫 문제가 여전히 "전혀 모르는 O/X"이고(이해도 0.05~0.12), 잘하는 편 학생은 맞는 4지선다(13개)가 4일 안에 동나 구간 밖(P 0.91) 문제로 밀립니다. 원인을 고치지 않고 증상만 누릅니다.

## 6. 남은 한계와 후속 제안

- **어려워하는 학생의 P는 여전히 75% 미만**(θ −3에서 0.45). 기존 설계의 "한계 1"(가장 쉬운 문항으로도 75% 미만)과 같은 문제이고, 해결은 문항이 아니라 은행 쪽입니다 → **커리큘럼 설계자에게 제안**: 난이도 0 문항을 강마다 1개 더(특히 개념 하나만 묻는 4지선다). 난이도 0~1 O/X도 몇 개 있으면 종류가 다양해집니다.
- **θ 1 근처는 난이도 2 4지선다가 13개뿐**이라 3~4일이면 동납니다. 그 뒤에는 E6(7일 지난 문항 재사용) 또는 구간 밖 문항으로 갑니다. 같은 제안: 난이도 2 4지선다 보강.
- **서버 기본 15강만 열린 경우**: θ −3 학생의 난이도 0 4지선다가 15개뿐이라 3일 뒤에는 난이도 1(4지선다·O/X가 고르기용 P 0.34로 같음)로 넘어갑니다. 큰 문제는 아니지만 QA 9번(열린 범위 15 vs 30)을 먼저 정리하면 좋습니다.
- QA 8번(진단 난이도 0 → b −2): 지금 `schema.sql` 255행은 이미 `when 0 then -2 when 1 then -1 when 2 then 0 else 1`로 logic.js와 같습니다(이 문서 작성 시점에 확인). 진단 채점은 c를 바꾸지 않는 것이 맞습니다(채점은 진짜 찍기 확률 기준).
- 데이터가 쌓이면(문항당 응답 10개 이상) 문항 b가 실제 응답으로 고쳐지므로, O/X 문항이 실제로 얼마나 쉬운지가 숫자로 드러납니다. 그때 E7 상한(2)을 다시 볼지 데이터 분석가와 확인합니다.

## 부록. 확인용 파이썬 코드 (저장소 맨 위 폴더에서 실행)

```python
import json, math, random
BANK = []
for f in ['questions_part1-3.json', 'questions_part4-6.json', 'questions_easy.json']:
    BANK += [q for q in json.load(open('03_교육기획팀/문항은행/' + f, encoding='utf-8')) if q['pool'] == 'practice']
B = {0: -2, 1: -1, 2: 0, 3: 1}
def und(th, q): return 1 / (1 + math.exp(-(th - B[q['difficulty']])))          # 찍기 뺀 이해도
def p_real(th, q): c = 1 / len(q['choices']); return c + (1 - c) * und(th, q)   # 앱의 진짜 P
SEL_C = {'NOW': None, 'A': None, 'B': None, 'C': 0.25, 'REC': 0.25}
CAP   = {'NOW': None, 'A': 1,    'B': None, 'C': None, 'REC': 2}
def p_sel(th, q, plan):
    c = SEL_C[plan]
    return p_real(th, q) if c is None else c + (1 - c) * und(th, q)
def pick(th, cand, plan, session):
    cap = CAP[plan]
    ox_used = sum(q['type'] == 'ox' for q in session)
    block = (cap is not None and ox_used >= cap) or (plan == 'B' and session and session[-1]['type'] == 'ox')
    if block:
        non = [q for q in cand if q['type'] != 'ox']
        if non: cand = non
    band = [q for q in cand if 0.75 <= p_sel(th, q, plan) <= 0.90]
    if band: return random.choice(band)
    return min(cand, key=lambda q: abs(p_sel(th, q, plan) - 0.82))
def run(th, plan, seed, days=4, per=5):
    random.seed(seed); used, out = set(), []
    for _ in range(days):
        session = []
        for _ in range(per):
            q = pick(th, [x for x in BANK if x['id'] not in used], plan, session)
            used.add(q['id']); session.append(q); out.append(q)
    return out
print(len(BANK), '문항')
for plan in ['NOW', 'A', 'B', 'C', 'REC']:
    for th in [-3, -2, -1, 0, 1, 2]:
        r = [run(th, plan, s) for s in range(500)]
        f = lambda n, key: sum(key(q) for o in r for q in o[:n]) / (len(r) * n)
        print(plan, th,
              'OX5 %.0f%%' % (100 * f(5, lambda q: q['type'] == 'ox')),
              'OX20 %.0f%%' % (100 * f(20, lambda q: q['type'] == 'ox')),
              'P5 %.3f' % f(5, lambda q: p_real(th, q)),
              'P20 %.3f' % f(20, lambda q: p_real(th, q)),
              '이해도5 %.2f' % f(5, lambda q: und(th, q)))
```
