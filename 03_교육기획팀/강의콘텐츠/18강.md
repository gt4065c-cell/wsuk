# 18강 SDK와 API로 웹사이트와 Firebase 연결하기
> 읽는 시간: 약 5분

## 핵심 개념
버튼을 누르면 DB에 있는 기록이 화면에 나타나요. 웹사이트는 어떤 통로로 기록을 가져올까요?
- API(기능을 부를 때 지키는 약속): 프로그램이 다른 기능을 쓸 때 따르는 정해진 방법이에요.
- SDK(만들기를 돕는 도구 꾸러미): 그 기능을 쉽게 부르도록 미리 만들어 둔 함수와 도구 모음이에요.

파이어베이스 웹 SDK를 쓰면 로그인이나 기록 읽기를 준비된 함수로 부를 수 있어요. SDK와 API는 둘 중 하나를 고르는 사이가 아니에요. SDK를 써서 API 기능을 부르는 거예요. 프로젝트 설정은 어느 프로젝트와 앱을 쓸지 알려 주고, DB 주소(databaseURL)는 어느 DB에 연결할지 정해요.

## 예시
준비된 연결 코드에서 세 곳을 확인해요.
1. 설정 값: projectId와 databaseURL이 콘솔에 보이는 실제 값과 같은지 봐요. 다른 프로젝트 값이 섞이면 로그인은 잘 되면서 기록만 보이지 않는 일이 생겨요. 인터넷 예제 값을 그대로 쓰면 안 돼요.
2. 준비 순서: 설정으로 앱을 준비(initializeApp)하고, 그 앱에서 DB를 꺼낸 뒤(getDatabase), 읽을 위치를 정해 읽어요. 함수 이름보다 이 순서가 중요해요.
3. 읽을 위치: 로그인한 사람의 연습 기록 아래 샘플 하나를 읽어요. 값이 없으면 "기록이 없어요"를, 권한이 없으면 따로 오류를 보여 줘요. 두 경우를 같은 빈 화면으로 숨기지 않아요.

읽기가 안 되면 설정, 로그인 여부, 위치, 규칙을 차례로 살펴요. SDK를 붙였다고 연결이 끝난 건 아니에요.

'키'라는 말도 조심해요. 웹 설정에 든 API 키는 어느 프로젝트인지 알려 주는 역할이고, 자료 보호는 인증과 규칙이 맡아요.

## 꼭 기억할 3가지
- API는 기능을 부를 때 지키는 약속, SDK는 만들기를 돕는 도구 꾸러미예요.
- SDK와 API는 경쟁 관계가 아니에요. SDK를 써서 API 기능을 불러요.
- 이름이 같은 'API 키'라도 쓰임이 달라요. AI 비밀 키는 화면 코드에 넣지 마요.
