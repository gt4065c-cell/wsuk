# 17강 인증과 권한을 구분하고 데이터 접근 막기
> 읽는 시간: 약 5분

## 핵심 개념
인증은 요청한 사람이 '누구인지' 확인하는 일이고, 권한은 그 사람이 '어떤 자료를 읽고 쓸지' 정하는 일이에요. Realtime Database에서는 보안 규칙(Security Rules)으로 접근을 정하고, 들어오는 값이 올바른지도 검사해요.

개인 연습 기록은 사용자 UID별로 칸을 나눠 둬요. 규칙은 "로그인한 사람의 UID와 칸 주인의 UID가 같을 때만 허락"이에요. 로그인했는지만 보면 남의 칸까지 열려 버려요. 그래서 '주인 조건'이 꼭 필요해요. 위쪽 칸에서 모두에게 문을 열어 두면 아래 규칙으로 막으려 해도 뜻대로 안 될 수 있으니, 넓게 열어 주는 설정은 넣지 않아요.

## 예시
실제 데이터가 없는 시험 환경(Emulator)에서 사용자 A와 B를 가정하고 네 가지를 시험해요.

| 요청 | 결과 |
|---|---|
| A가 자기 칸에 기록 | 허용 |
| A가 B의 칸에 기록 | 거부 |
| 로그인 안 한 요청 | 거부 |
| 점수에 글자나 범위를 벗어난 값 | 거부 |

버튼을 감춰도 누군가 요청을 직접 만들어 보내는 경우까지 생각해서 시험하는 거예요. 반대로 허용될 요청이 잘 통과하는지도 중요해요. 다 막으면 안전해 보여도 서비스가 멈추거든요. 그리고 숫자 형식과 범위가 맞아도, 실제로 맞힌 답이라는 보장은 없어요.

규칙 하나가 모든 보안을 대신하지는 않아요. 서버의 관리자 권한은 이 규칙을 건너뛸 수 있어서, 서버 코드에서도 사용자와 입력을 다시 확인해야 해요. 권한 오류가 난다고 전체 공개로 바꾸지 않아요.

## 꼭 기억할 3가지
- 인증은 '누구냐', 권한은 '무엇을 읽고 쓸 수 있냐'를 정해요.
- 로그인만 확인하면 남의 기록 칸까지 열려요. 내 UID 칸만 허락해요.
- 규칙 시험은 막아야 할 요청과 통과해야 할 요청을 둘 다 해 봐요.
