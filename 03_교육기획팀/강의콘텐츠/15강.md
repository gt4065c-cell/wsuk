# 15강 Firebase 구성과 Realtime Database 선택하기
> 읽는 시간: 약 5분

## 핵심 개념
Firebase(파이어베이스) 화면에는 서비스가 많아 처음엔 막막해요. 이번 실습에서 쓰는 건 세 가지예요.
- 인증(Auth): 학생이 누구인지 로그인으로 확인해요.
- Hosting(호스팅): 웹 파일을 방문자에게 내줘요.
- 데이터베이스: 응시 기록을 남기고 관리해요.

파이어베이스의 데이터베이스는 두 종류예요. 둘 다 실시간으로 내용을 맞춰 주지만 담는 모양이 달라요. 클라우드 파이어스토어는 문서와 묶음(컬렉션) 단위로, 리얼타임 데이터베이스는 폴더처럼 단계가 이어지는 JSON(이름과 값의 묶음) 나무 구조로 다뤄요.

이번 실습은 작은 기록이 바뀌는 걸 쉽게 보려고 리얼타임 데이터베이스(이하 실시간 DB)를 써요. 그렇다고 모든 프로젝트에서 이걸 골라야 한다는 뜻은 아니에요. 여러 종류의 기록과 복잡한 찾기가 필요하면 요구에 맞춰 따져 봐요. Google도 새로 시작하는 고객에게는 파이어스토어부터 검토하라고 안내해요.

## 예시
| 하고 싶은 일 | 맡는 서비스 |
|---|---|
| 학생이 누구인지 확인 | 인증(Auth) |
| 게임 주소 제공 | Hosting |
| 응시 기록 남기기 | 데이터베이스(이번엔 실시간 DB) |

헷갈리기 쉬운 장면도 있어요.
- 이름이 비슷한 연습 프로젝트가 많으면, 이름 말고 프로젝트 ID로 구분해요.
- 같은 플랫폼이라도 웹 파일을 올렸다고 DB가 저절로 이어지지는 않아요.
- 학생에게 이름을 적게 하는 화면은 인증이 아니에요. 이름은 남이 똑같이 적을 수 있지만, 인증은 계정의 주인을 확인하는 일이에요.
- 연습용 DB는 문을 잠가 둔 상태예요. 데이터가 안 읽힌다고 '모두 공개'로 풀지 않아요.

## 꼭 기억할 3가지
- Firebase는 로그인 확인, 웹 파일 제공, 기록 보관을 각각 다른 서비스가 맡아요.
- 이번엔 기록 변화를 쉽게 보려고 실시간 DB를 골랐을 뿐, 늘 정답은 아니에요.
- 이름을 적게 하는 화면은 로그인 확인(인증)이 아니에요.
