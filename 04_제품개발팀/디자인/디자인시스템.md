## 0. 디자인 원칙 5가지

1. **3초 규칙** — 화면마다 "지금 누를 버튼"은 진한 색 버튼 **하나**. 나머지는 테두리 버튼이나 글자 링크로 약하게.
2. **유치하지 않은 게임 느낌** — 캐릭터·이모지·폭죽 없음. 대신 ① 칸으로 나뉜 진행 막대(한 칸씩 채워지는 손맛) ② 답 확정 순간의 짧은 반응(0.2초) ③ 결과 화면의 "문항 발자국"(칸마다 ✓/✕)으로 "한 판을 깼다"는 느낌을 줍니다. XP·배지·순위는 이번 버전에 없습니다(결재1 연기).
3. **점수는 내 화면에만** — 결과 화면에 공유·순위·남과 비교 버튼 없음. "이 결과는 이 휴대폰에만 있어요" 문구를 늘 같이 둡니다.
4. **색만으로 말하지 않기** — 정답/오답, 선택됨, 잠김은 모두 **색 + 모양(아이콘·테두리) + 글자**로 함께 표시합니다(색약 참가자 배려).
5. **휴대폰 글자 크기를 키워도 안 깨지게** — 모든 크기를 `rem`(휴대폰 글자 설정을 따라 커지는 단위)으로 정하고, 가로로 넘치는 요소를 만들지 않습니다(PRD D-05, D-06).

## 1. 색 (CSS 변수 이름 그대로 개발에 사용)

### 색 규칙
- 정답은 **청록빛 초록**, 오답은 **주홍**. 일반 빨강·초록보다 적록 색약에서 밝기 차이가 커서 덜 헷갈립니다. 그래도 색만 믿지 않습니다(4장).
- 어두운 모드는 휴대폰 설정(`prefers-color-scheme`)을 따르고, 화면 위 토글로 바꿀 수도 있게 합니다(시안의 [밝게/어둡게]).
- 순수 검정(#000)·순수 흰색 글자 위 순수 검정 바탕은 쓰지 않습니다(눈부심).

### 글자 크기 (최소 14px — 그보다 작은 글자 금지)

| 이름 | 크기 | 굵기 | 쓰는 곳 |
|---|---|---|---|

| `title` | 1.375rem (22px) | 700 | 화면 제목 |
| `question` | 1.1875rem (19px) | 600 | 문제 글 |
| `body` | 1.0625rem (17px) | 400~500 | 보기, 해설, 버튼 글자 |

## 4. 구성 요소

### 4-1. 버튼
| 종류 | 모양 | 쓰는 곳 |
|---|---|---|
| 주 버튼 | `--primary` 바탕, 글자 17px 700, 높이 52px, 폭 100% | [시작하기] [답 확정] [다음 문제] [다시 풀기] |
| 보조 버튼 | 테두리 1.5px `--border`, 바탕 `--surface` | [틀린 문항 다시 보기] [다른 세트] [새로 시작] |
| 글자 버튼 | 밑줄 글자, 높이 44px 확보 | [처음 화면으로] 같은 드문 동작 |
| 눌리지 않는 상태 | 투명도 45% + 글자 "보기를 먼저 고르세요"를 버튼 위에 작게 표시 | 보기 고르기 전 [답 확정] |
| 누를 때 | 0.98배로 살짝 작아짐(0.1초). 움직임 줄이기 설정을 켠 사람에게는 끔 | 모든 버튼 |
| 키보드 초점 | 3px `--primary` 바깥선 | 모든 누르는 곳 |

- 연타 방지: [답 확정]·[다음 문제]는 한 번 누르면 바로 잠깁니다(PRD B-05, B-07).

### 4-2. 카드
- 세트 카드: 왼쪽에 **부 번호 큰 숫자**("1부"), 가운데 제목·범위("01~05강"), 오른쪽 문항 수("10문항"). 고르면 테두리 2px `--primary` + 오른쪽 위 ✓ 표시 + 글자 "선택됨"(화면 읽기 프로그램용).
- 분량 고르기: 두 칸짜리 선택 막대 [8문항 · 무작위] [세트 전체]. 고른 칸은 진한 바탕 + ✓.

### 4-3. 보기 버튼 (가장 중요)
| 상태 | 색 | 모양 | 글자 |
|---|---|---|---|
| 기본 | `--surface`, 테두리 `--border` | 왼쪽에 동그라미 번호 ①②③④ (OX는 큰 O / X) | 보기 내용 |
| 고름(확정 전) | `--primary-weak`, 테두리 2px `--primary` | 번호 동그라미가 꽉 찬 색 | — |
| **정답 보기**(확정 후) | `--correct-bg`, 테두리 2px **실선** `--correct` | 오른쪽에 **✓ 아이콘** | 꼬리표 **"정답"** |
| **내가 고른 오답**(확정 후) | `--wrong-bg`, 테두리 2px **점선** `--wrong` | 오른쪽에 **✕ 아이콘** | 꼬리표 **"내 답"** |
| 나머지(확정 후) | 투명도 55% | — | — |

- 정답을 맞혔으면 그 보기에 ✓ + "정답 · 내 답" 꼬리표.
- 흑백으로 인쇄해도 **실선 + ✓ = 정답, 점선 + ✕ = 내 답(오답)**으로 구분됩니다.
- 확정 후 보기는 눌러도 반응하지 않습니다(PRD B-06). 화면 읽기 프로그램에는 "잠김"으로 알립니다.

### 4-4. 채점 알림 막대 (해설 맨 위)
| 결과 | 표시 |
|---|---|
| 정답 | ✓ 동그라미 아이콘 + **"정답입니다"** (청록 초록 글자, 연한 바탕) |
| 오답 | ✕ 동그라미 아이콘 + **"아쉬워요, 정답은 ③ ○○○"** (주홍 글자). 번호는 **섞인 뒤 화면 번호**, 보기 내용을 함께 씀(PRD F3-2) |

- 그 아래 순서: **해설** → (자주 고르는 오답을 골랐을 때만) **"이렇게 헷갈리기 쉬워요"** 상자(노란 바탕 + 전구 대신 "!" 동그라미 아이콘) → **근거 강의**(작은 글자, "근거: 11강 핵심 개념").
- 알림은 화면 읽기 프로그램이 바로 읽도록 `aria-live`로 둡니다.

### 4-5. 진행 표시
- 맨 위: 세트 이름 · **"3 / 8"** · 문항 표지(`L11-Q1`, 고정폭 글꼴, 테두리 상자).
- 그 아래 **칸 진행 막대**: 문항 수만큼 칸. 지난 칸은 ✓(정답)/✕(오답) 작은 표시가 들어간 색 칸, 지금 칸은 테두리 굵게, 남은 칸은 빈 칸. 칸이 너무 좁아지면(15칸 이상) 표시 없이 색만.

### 4-6. 결과 화면
- "K7M2PX님 결과" (코드는 고정폭) → 큰 숫자 **"4 / 6 정답"** → 문항 발자국(칸마다 ✓/✕와 문항 표지).
- 안내 한 줄: "이 결과는 이 휴대폰 화면에만 있어요. 교수님을 포함해 아무에게도 전송되지 않아요."
- 버튼 순서: [틀린 문항 다시 보기](보조) → [다시 풀기 — 새로 섞어요](주) → [다른 세트](보조).
- 다 맞혔을 때: 틀린 문항 다시 보기 버튼 대신 "틀린 문항이 없어요" 글자(버튼 없음).
- 칭찬 문구는 사실만: "6문항 모두 정답입니다" / "틀린 2문항의 해설을 다시 보면 좋아요". "천재!", "대박" 같은 과장 금지.

### 4-7. 교수님 지정 링크 모드 표시 (F6)
- 화면 맨 위에 **고정 띠**: 🔗 대신 "링크" 글자 아이콘 + **"교수님 지정 링크 · 팀 연습 6문항 · 순서 고정"**.
- 첫 화면 안내가 바뀜: "코드를 넣으면 바로 1번 문제가 열려요. 팀원 모두 같은 문제·같은 보기 순서예요."
- 문항 표지(`L11-Q1`)를 더 크게(16px) — 팀원끼리 "같은 문제 맞죠?" 확인용.
- 링크에 없는 문항이 섞여 있으면 첫 문제 위에 노란 안내 상자: "이 링크에 없는 문항이 1개 있어요. 있는 문항만 진행해요. 교수님께 알려 주세요."

|---|---|---|
| 개인정보 안내 | `--surface-2` 바탕, 자물쇠 대신 "i" 동그라미 | "이 코드는 화면에만 표시되고 어디에도 저장·전송되지 않아요" |
| 입력 오류 | 입력칸 테두리 `--wrong` + 칸 아래 ✕ 아이콘 + 글자 | "카드에 적힌 영문·숫자 코드를 넣어 주세요" |
| 이어 풀기 | 카드 + 주 버튼 [이어 풀기] + 보조 [새로 시작] | "풀던 연습이 있어요 · 3부 연습 4 / 8" |
| 저장소 꺼짐 | 화면 아래 한 줄, `--note` 색 | "이 브라우저에서는 이어 풀기가 꺼져 있어요. 풀기·채점은 정상이에요." |

## 6. 사용성 점검표 (디자이너 자체 점검 — 개발 후 QA가 다시 확인)

| 항목 | 기준 | 시안 상태 |
|---|---|---|
| 누르는 곳 크기 | 44px 이상 | 주 버튼 52px, 보기 56px 이상, 토글 44px |
| 최소 글자 | 14px | 가장 작은 글자 14px(문항 표지·진행 수) |
| 색약 구분 | 색 + 아이콘 + 글자 + 테두리 모양 | 정답 ✓·실선·"정답" / 오답 ✕·점선·"내 답" |
| 360px 폭 | 가로 스크롤 없음 | 여백 16px로 줄임, 긴 보기는 줄바꿈 |
| 글자 크기 최대 | 겹침·잘림 없음 | rem 단위, 높이 고정 없음(최소 높이만) |
| 움직임 줄이기 | 애니메이션 끔 | `prefers-reduced-motion` 대응 |
| 3초 규칙 | 화면마다 진한 버튼 1개 | 결과 화면도 [다시 풀기] 하나만 진함 |
| 개인정보 | 이름·학번 입력칸 없음, 한글 입력 거절 | 코드 칸 하나뿐 |

## 7. A안 / B안 비교 (캡틴이 고를 것)

| | **A안 "차분한 연구노트" (추천)** | B안 "야간 작전실" |
|---|---|---|
| 느낌 | 밝은 종이 위 남색 펜. 대학 강의 자료 같은 신뢰감 | 어두운 바탕 + 호박색. 게임 화면(HUD) 같은 몰입감 |
| 모양 | 둥근 모서리, 옅은 그림자 | 각진 모서리, 테두리만, 숫자·표지 강조 |
| 기본 모드 | 밝은 모드 | 어두운 모드 |
| 장점 | 강의실 밝은 조명·프로젝터에서 잘 보임, 연령대 넓게 무난 | "게임 같다"는 첫인상이 강함, 저녁 복습 때 눈이 편함 |
| 걱정 | 게임 느낌이 상대적으로 약함 | 밝은 강의실에서 휴대폰 밝기가 낮으면 덜 보일 수 있음, 일부 성인에게 "가벼워 보임" 가능 |
| 추천 이유 | 대상이 **성인 교수자**이고 수업 중 밝은 강의실에서 쓰므로 A안. 게임 느낌은 칸 진행 막대·문항 발자국으로 충분히 냄 | — |
