### 팀 목표 규칙 (이름 = 실제 의미, 교훈노트 2026-11-02)
- **"주간 팀 참여 목표"** = 활동 중인 팀원 **모두** 이번 주(월~일, 한국 날짜) 15문항을 끝까지 풀기.
- 팀 진행 = 팀원마다 min(내 문항 수, 15)를 더함 → 한 사람이 혼자 다 채울 수 없음.
- 경험치를 받은 풀이만 셈(같은 문제 다시 풀기, 하루 상한을 넘은 풀이는 안 셈).
- 설계 문서의 "학습목표 달성"(주간 공통 점검 점수 평균)과는 **다른 목표**입니다. 화면에도 "참여 목표"라고만 씁니다.

### SQL 66개에서 확인한 것 (임시 DB, 가짜 학생·가짜 이메일)
- 팀 짜기: 별명 있고 팀 켠 9명 → 3팀×3명, 실력 상위 3명이 서로 다른 팀, 이미 팀 있으면 거절, 다른 기수는 따로.
- 학생 권한: `teams` 표 읽기·쓰기 불가, 자기 팀 직접 변경 불가, 팀 짜기·내부 도우미 실행 불가.
- 팀 요약: 팀원 칸은 별명·나·쉼뿐, 진행 35/45(XP 0·지난주 기록 제외) → 45/45 달성, 쉬기 시 목표 30, 다른 팀 학생에게 우리 팀 정보 안 보임.
- 교수 확인: 익명 계정이 교수 이메일을 흉내 내도 거절, 메일 확인 안 된 계정 거절, admins에 없는 이메일 거절, JWT 이메일과 계정 이메일 불일치 거절, 대소문자 무시.
- 통계: 학생마다 첫 풀이만, 다른 기수 제외, 가장 많이 고른 오답, 응답 3명 미만 문항 제외, 학생 코드·별명·θ 없음, 지난주 따로 계산.
- 권한 표: RLS 꺼진 표 0개, 로그인한 사람이 부를 수 있는 새 함수는 정확히 5개.
- 30번 파일을 **두 번 실행해도 오류 없음**, M1 함수 본문은 적용 전후 같음.

## 3. 캡틴이 확인하는 방법 (1-2-3, 로컬 모드)
1. `04_제품개발팀/app2` 폴더에서 `python3 -m http.server 8010 --bind 127.0.0.1 --directory public`
2. 학생 화면: 크롬 `http://127.0.0.1:8010` → `TEST23` → 진단 후 홈 아래쪽 **팀 카드**. 교수 화면: `http://127.0.0.1:8010/admin.html` → `prof@example.com`
3. 다 봤으면 터미널에서 Ctrl + C

## 4. 비서실장이 할 일 (DB 적용)
1. `04_제품개발팀/app2/supabase/30_m2_teams_admin.sql` 적용(schema.sql 다음, 한 번 더 실행해도 안전). 파일 맨 아래 "점검" 쿼리 3개로 RLS·권한 확인.
2. 꼭 확인할 것: `lu_is_admin()`이 `auth.users`를 읽습니다 — 실제 Supabase에서 함수 주인(postgres)이 `auth.users`를 읽을 수 있는지(임시 DB에서는 흉내라 확인 못 함).
3. 교수 계정: Authentication → Users에서 교수 이메일 계정 미리 만들기, Redirect URLs에 교수 화면 주소 추가, "Confirm email" 켜 둔 채 유지, `insert into admins (email) values (…)`는 SQL Editor에서만(이메일을 저장소에 쓰지 않음).

## 5. 알려진 문제와 남은 위험
| 항목 | 내용 | 대책 |
|---|---|---|
| 실DB 미검증 | 모든 시험이 가짜 서버·임시 DB | 비서실장 MCP 적용 후 실제 호출 확인 |
| 교수 이메일 가로채기 | Supabase에서 "Confirm email"을 끄면, 교수 계정이 생기기 전 누군가 그 이메일로 먼저 가입해 메일 확인 없이 들어올 수 있음 | 메일 확인 켜 두기 + 교수 계정을 먼저 만들기. 서버도 "메일 확인 끝난 계정"만 교수로 인정 |
| 등록 여부가 드러남 | 등록 안 된 이메일은 "등록되지 않은 이메일"로 안내 → 어떤 이메일이 등록됐는지 짐작 가능 | 교수 화면은 교수 1명용이라 위험 작음. 필요하면 문구 통일 |
| 매직링크 다른 기기 | 메일을 휴대폰에서 열면 휴대폰 브라우저에 로그인됨 | 화면에 "이 브라우저에서 누르세요" 안내, 6자리 숫자 방식은 메일 양식에 `{{ .Token }}`이 있어야 함(미확인) |
| 5명 기수 | 인원÷4 올림 규칙이라 5명이면 3+2 | `admin_move_student`로 조정, 설명은 SQL 주석·README |
| 팀 짜기 기준 | 설계는 "진단 + 기준 점검 정답률", 지금은 숨은 실력값 θ(진단으로 시작, 연습 반영)로 대신 | 기준 점검을 만드는 다음 차수에 바꿀 수 있음. "평균 10%p 벗어나면 맞바꾸기"는 아직 없음 |
| 교수 화면의 학생 활동 ✔ | 교수에게는 팀원별 "그 주에 1문항 이상" 여부를 보여 줌(팀 합치기 판단용) | 개인 문항 수·XP는 교수에게도 안 보임 |
| 배포본 | 저장소의 `deploy_public/`(M1 체험판)은 다시 만들지 않음 | 다시 만들고 올리는 것은 결재 후 |
| 공개 저장소 | 문제 없음: 진짜 이메일·코드·키 없음(가짜는 example.com / TEST23) | 배포 도구가 이메일 주소를 검사 |
