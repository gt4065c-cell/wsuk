## 1. 만든 것

|---|---|

## 3. 진짜 Supabase 접속 시도

- 이 작업 컴퓨터에서 `https://ebquzmmvkknknpmiqnyk.supabase.co/auth/v1/health`로 접속해 봤지만 회사 중계기(프록시)가 막았습니다(응답 403). → **실DB 미검증**.
- 지시대로 진짜 DB에는 쓰기 시험을 하지 않았고, 코드 카드 만들기(`admin_make_codes`)도 부르지 않았습니다.
- 비서실장 확인 부탁(MCP): 시험용 코드 1개로 `?mode=supabase` 흐름 그대로 claim → 진단 12 → 연습 5 → 새로고침 → 홈 XP 50.

## 4. 알려진 문제·남은 위험

| # | 내용 | 크기 | 제안 |
|---|---|---|---|
| 1 | **실DB 미검증** — 가짜 서버는 schema.sql을 보고 흉내 낸 것이라, 진짜 서버의 세부 동작(배열 인자 `text[]`·`int[]` 전달, 날짜 모양 등)은 실제로 돌려 봐야 확정 | 중 | 비서실장 MCP 시험(3장) |
| 2 | **같은 와이파이에서 한꺼번에 로그인** — Supabase는 익명 로그인 수를 IP(인터넷 주소)마다 시간당 제한함(기본값 시간당 30번으로 알고 있음, (미확인)). 강의실 30명이 같은 와이파이로 동시에 들어오면 막힐 수 있음 | **중~상** | 수업 전 Supabase → Authentication → Rate Limits에서 익명 로그인 한도 확인·상향(무료, 결제 없음) |
| 3 | 익명 계정이 쌓임 — [다른 코드로 들어가기]·새 기기마다 임시 계정이 하나씩 생김(학생 기록은 코드에 하나로 모임). 누구나 화면을 열어 [들어가기]를 누르면 빈 계정 생성 가능 | 하 | 나중에 오래된 빈 익명 계정 정리, 필요하면 로봇 방지(CAPTCHA) |
| 4 | 정답 확인을 화면도 함 — 연습 정답은 원래 학생이 읽을 수 있는 값이라 화면이 바로 채점하고, 서버(`close_item`)도 다시 채점해 결과·XP를 정함. 둘이 다르면 콘솔에 경고만 남기고 화면 결과 이름은 화면 값 | 하 | M2에서 서버 결과 이름을 화면에 쓰도록 바꿀지 결정 |
| 5 | 진단을 10~11문항에서 끝내면 해설은 답한 문항만 나옴(서버 `diag_finish` 모양 그대로) | 하 | 설계 의도와 같은지 기획 확인 |
| 6 | 저장소가 공개라 `public/data/hints.js`(검토 전 힌트)·`dev_diag_key.js`(진단 정답)는 깃허브에서 누구나 볼 수 있음 — 배포본에는 빠지지만 저장소에는 남음 | 기존 위험 | CLAUDE.md 7장대로 캡틴 결정(공개 유지) 범위 안. 평가 반영이 생기면 재확인 |
| 7 | 시험 실행 때 `screenshots/` 사진 6장이 다시 찍혀 바뀜(문제가 무작위로 나와서). 내용은 같은 화면 | 하 | 커밋 때 함께 넣거나 되돌리면 됨 |

## 5. 캡틴이 확인하는 방법 (1-2-3)
1. 터미널에서 `04_제품개발팀/app2` 폴더로 가서 `python3 -m http.server 8010 --bind 127.0.0.1 --directory public`
2. 크롬에서 `http://127.0.0.1:8010` → 지금과 같은 로컬 모드(노란 띠). `http://127.0.0.1:8010/?mode=supabase` → Supabase 모드(노란 띠 없음, 진짜 코드 카드 필요)
3. 다 봤으면 터미널에서 Ctrl + C
