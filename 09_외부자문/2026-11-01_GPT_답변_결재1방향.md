### 대학 수업용 「수준별 퀴즈 대결」 시범 운영안에 대한 비판적 검토

판정: 조건부 추진 — 현재 설계는 수정 필요

결론부터 말씀드리겠습니다.

6주 안에 코딩 초보 교수가 AI 코딩 에이전트의 도움으로 퀴즈 웹앱을 만드는 것은 현실적입니다. 그러나 지금 제안하신 여섯 가지 기능을 모두 구현해 20~50명이 안정적으로 사용하고, 교육적 효과까지 확인하겠다는 목표는 과도합니다.

제가 가장 우려하는 것은 기술적인 실패보다 교육적으로 불공정한 경쟁을 정교한 알고리즘으로 포장할 가능성입니다.

권고는 다음과 같습니다.

* 이번 학기: 기존 퀴즈 도구로 수업을 운영하고, 향상점수와 팀 순위는 스프레드시트로 계산합니다.
* 동시에: AI 코딩 에이전트로 소규모 웹앱을 개발하되 실제 수업 운영과 분리해 검증합니다.
* 겨울방학: 학습 데이터와 사용자의 반응을 바탕으로 수준별 문제 출제와 실시간 순위 기능을 결합합니다.

### 1. 가장 큰 약점 3가지와 대안

#### 약점 ① 난이도 조절과 향상점수가 충돌합니다 (가장 심각한 설계 문제)

현재 설계는 학습자의 수준에 따라 서로 다른 난이도의 문제를 주면서 정답률의 향상을 평가하려는 구조입니다.

| 수강생 | 지난 점수 | 이번 점수 | 향상 |
|---|---|---|---|
| A (초급) | 60% | 90% (쉬운 문제) | +30%p |
| B (고급) | 80% | 75% (어려운 문제) | -5%p |

A가 더 많이 향상되었다고 판단할 근거가 부족합니다. 문제 난이도가 다르므로 정답률을 직접 비교할 수 없습니다. 오히려 B가 더 많이 배웠을 가능성도 있습니다. 난이도를 높였는데 정답률이 떨어진 수강생은 자신의 학습 진전이 벌점으로 돌아왔다고 느낄 수 있습니다. 게다가 목표 정답률 75~90%를 유지하도록 설계하면 서로 다른 실력을 가진 참가자의 점수가 비슷하게 모여, 정답률이 학습 수준을 구분하는 지표로서 가치가 떨어질 수 있습니다.

대안: 학습과 경쟁을 분리해야 합니다.
* 수준별 연습: 각자의 실력에 맞는 문제를 풀고 즉시 해설을 받습니다.
* 향상도 평가: 모두가 난이도가 비슷한 공통 문항 또는 비교 가능한 평행검사 문항을 풉니다.
* 팀 점수: 공통 평가에서 개인별 향상도를 계산해 합산하거나 평균을 냅니다.

기존 STAD 협동학습은 개인의 기준 점수에 비례한 향상점수를 팀 성과에 반영하는 방식이지만, 점수를 공정하게 비교할 수 있다는 전제가 중요합니다.

#### 약점 ② 진단 문항 3~5개로는 수준을 안정적으로 판별하기 어렵습니다

5문항 중 4개를 맞히면 80%, 한 문제만 더 틀려도 60%입니다. 한 문항의 영향이 너무 큽니다. 5개 문항만으로 실력을 3단계로 구분하면 오분류 위험이 큽니다. 54개 문항도 충분하지 않습니다. 난이도별 18개뿐이라 여러 차례 게임을 하면 문제 암기 효과와 실제 학습을 구별하기 어렵습니다.

대안: 이번 학기에는 3단계 자동 판정을 포기합니다. 첫 진단은 10~12문항으로 늘리고, 초기 수준 참고자료로만 사용합니다. 진단 결과로 팀을 구성할 수는 있지만 정확한 실력 등급으로 취급하지 않습니다. 학습용 문항과 평가용 문항을 구분하고, 평가 문항은 사전에 노출하지 않습니다.

#### 약점 ③ 너무 많은 기능이 동시에 실패할 수 있습니다

별명 접속, 자동 수준 조절, 개인 점수 기록, 팀 배정, 향상점수 계산, 실시간 순위표는 각각 별개의 개발 과제이고 서로 영향을 줍니다(새로고침 중복 접속, 늦게 들어온 참가자 처리 등). "50명 수용 가능"과 "50명 수업에서 안정적으로 작동"은 다릅니다.

대안: 첫 웹앱의 기능을 네 가지로 제한합니다 — **별명 입장, 공통 퀴즈 응시, 자동 채점, 결과 저장**. 팀 편성과 향상점수 계산은 스프레드시트가 맡고, 순위는 활동 종료 후 보여 줍니다.

### 2. 코딩 초보 교수가 6주 안에 만들 수 있습니까?

작동하는 시제품 제작은 가능하지만, 검증된 수업 운영 시스템까지 완성할 수 있을지는 확실하지 않습니다. 위험은 코드 작성 속도가 아니라, AI가 만든 코드의 오류를 발견하고 수정이 다른 기능을 망가뜨리지 않았는지 확인하는 과정입니다.

| 원래 계획 | 수정안 |
|---|---|
| ① 진단 3~5문항 | 10~12문항 사전 진단 |
| ② 자동 난이도 조절 | 겨울방학으로 연기 |
| ③ STAD 향상점수 | 스프레드시트 계산 |
| ④ 3~4인 혼합수준 팀 | 교수가 직접 배정 |
| ⑤ 팀 순위만 공개 | 활동 종료 후 공개 |
| ⑥ 기존 도구 예비 세트 | 실제 수업용 기본 도구로 사용 |

6주 실행 계획: 1주 문항 검수·진단/평가 문항 구분·기존 도구 테스트 → 2주 기존 도구+스프레드시트로 5~10명 예비 실험 → 3주 별명 접속·퀴즈·채점·결과 저장 웹앱 구현 → 4주 중복·새로고침·이탈·재접속 테스트 → 5주 동시 접속 모의 수업 → 6주 검증된 도구로 본 시범, 자체 웹앱은 안전한 범위에서만 시연.

무료 서버: Firebase 무료 요금제 가능. (답변 주장: Firestore 무료 하루 읽기 5만·쓰기 2만, Realtime Database 무료 동시 연결 100개 — **미검증**). 정답 검증과 점수 저장을 브라우저에서만 하면 점수 조작이 가능하므로, 정식 경쟁 운영 전에는 조작 방지와 실제 동시 접속 테스트가 필수.

### 3. 성인 교수자 대상 팀 경쟁의 역효과

위험 수준: 중간~높음 (조건부 추정, 정확한 확률은 확실하지 않음). 동료 앞에서 모르는 모습을 드러내는 부담이 클 수 있음.

| 상황 | 우려 | 대응 |
|---|---|---|
| 다른 교수 앞에서 오답 | 체면 부담 | 개인 정답률 비공개 |
| 초급 참가자로 팀 배정 | 낮은 수준으로 분류됐다는 인식 | 수준 명칭 미공개 |
| 팀 내 성적 차이 | 팀에 피해를 준다는 압박 | 개인 점수·기여도 비공개 |
| 빠른 응답 경쟁 | 손가락 속도 평가 | 속도 가산점 제외 |
| 게임식 화면 | 유치하다는 반응 | 전문적 시뮬레이션 형식 |

근거: Hanus & Fox(2015) 순위표·배지 수업에서 시간이 갈수록 동기·만족 감소 / 2024년 대학 순위표 연구 22건 체계적 문헌고찰 — 설계에 따라 효과가 달라짐 / 2023년 메타분석 — 연습시험은 평균적으로 시험불안을 낮춤. 문제는 퀴즈보다 "다른 사람 앞에서 평가받는 방식"일 가능성이 큼.

권하는 운영: 이름을 "게임"보다 **"AI Agent 실무역량 팀 챌린지"**로. 첫 회차는 팀 대결 없이 개인 연습 + 익명 집단 결과만. 이후 팀 단위로 풀되 개인 수준·점수는 숨김. 팀 순위는 최종 결과에서만, 원하지 않는 참가자에게 비경쟁 참여 선택권. 최하위 팀을 강조하지 말고 목표를 달성한 모든 팀을 인정. 활동 직후 익명 설문(재미·학습 도움·부담·재참여 의사). 팀 간 1등 경쟁보다 각 팀이 향상 목표를 달성하는 구조 권장.

### 4. 직접 제작 vs 기존 도구

결정권자라면 이번 학기에는 **기존 도구 + 스프레드시트**를 선택. 자체 개발은 별도 실습 프로젝트로 병행.

| 기준 | 직접 제작 | 기존 도구 + 스프레드시트 |
|---|---|---|
| 6주 내 구현 | 가능하나 불확실 | 높음 |
| 수업 중 안정성 | 사전 검증 필요 | 상대적으로 유리 |
| 수준별 자동 출제 | 구현 가능 | 제한적 |
| 향상점수 계산 | 별도 개발 필요 | 수식으로 처리 |
| 학생에게 개발 사례 제시 | 매우 적합 | 제한적 |
| 향후 확장성 | 높음 | 외부 서비스에 의존 |

도구 추천: **Socrative 1순위**(무료 활동당 50명, 저장 퀴즈 5개, 보고서 30일, 팀 활동 Space Race, 개인별 정답 보고서 — 무료 Excel 내보내기는 확실하지 않음, 50명이 최대치라 여유 없음). **Blooket 예비**(무료 60명, 단 상세 보고서 스프레드시트 다운로드는 유료 Plus라는 주장 — **미검증**). Kahoot!은 계정 유형별 한도 확인 필요.

향상점수: 공통 난이도 평가에서 기준점수 대비 향상을 0·10·20점으로 환산, 90점 이상 유지자도 만점 가능하게 보정(STAD식 간소화 규칙). 시범 전에 공개·고정. 팀 점수는 합계가 아니라 평균.

첫 시범 합격 기준(제안값, 연구 검증 기준 아님): 접속·완료율 90% 이상 / 응답·점수 기록 누락·중복 0건 / 채점 정확성 100% 일치 / 학습 도움 긍정 70% 이상 / 중간 이상 심리적 부담 10% 이하 / 재참여 의사 70% 이상.

### 5. 놓친 위험 5가지

1. 향상점수를 노린 진단 일부러 못 보기 + 천장효과 → 초기 수준을 여러 활동으로 추정, 높은 성취 유지도 인정, 진단을 경쟁 점수와 즉시 연결하지 않음
2. 별명만으로 개인정보 문제가 사라지지 않음(서로 아는 교수끼리 짐작 가능) → 무작위 참가자 코드, 최소 데이터, 삭제 기한, 연구 목적이면 별도 동의. 강의 개선용 조사와 학술 연구 구분
3. 정답 조작·중복 접속 → 답안은 1회 확정, 점수는 신뢰할 수 있는 곳에서 검증, 강의실 Wi-Fi에서 재접속·중복 제출 시험
4. 객관식 퀴즈가 실무 역량을 측정하지 못함 → 퀴즈는 개념 이해·참여 보조지표, 실무 역량은 과제·결과물로 평가
5. 재미있어도 교육 효과 입증은 아님(새로움·암기 효과) → 사전·사후 + 1주 뒤 지연 평가, 일반 퀴즈와 비교. 이번 학기는 사용 가능성·수용성 검증 우선, 효과 검증은 2027년

### 최종 의사결정 (ChatGPT)

이번 학기: 기존 도구 + 향상점수 실험 → 겨울방학: 시범 데이터 기반 웹앱 개선 → 2027년 1학기: 수준별 자동 출제 확장 검증.

검증할 가설: "학습 수준이 서로 다른 성인 학습자들이, 서로의 절대 실력이 아니라 개인별 성장에 기여하는 방식으로 경쟁하면 참여 의욕과 학습 경험이 개선되는가?"

프로젝트의 성공을 '6주 만에 앱을 완성했는가'가 아니라 **'성인 학습자에게 공정하고 부담이 적은 팀 학습 방식의 가능성을 확인했는가'**로 정의할 것.
