## 판정
조건부 승인 · 웹앱 범위 축소 권고. 가장 큰 위험은 해킹보다 **점수의 타당성 부족**(실제 성장을 제대로 재지 못하면 보안이 완벽해도 효과를 잘못 판단).

## 1. 가장 큰 약점 3가지
| 우선순위 | 약점 | 대안 |
|---|---|---|
| 1 | 성장하지 않아도 성장 목표 달성 | 유지·성장·숙달 구분, 팀 달성 기준 수정 |
| 2 | 8문항 평가의 우연성과 난이도 차이 | A·B·C 동등성 검토, 원점수 변화 함께 기록 |
| 3 | 웹앱 인증·보안이 실제 보장보다 강하게 표현됨 | 평가 기능 제외 유지, 서버 규칙 검증, 코드 강화 |

## 2. 1차 지적 판정
① 난이도·향상점수 충돌: 부분 해결(성장과 절대 성취가 한 점수에 섞임) / ② 진단 부족: 부분 해결(8문항 측정오차·동등성) / ③ 기능 과다: 부분 해결(인증·권한·CSV·보안 테스트 부담) / ④ 체면 부담: 부분 해결(팀 평균으로 개인 추측 가능) / ⑤ 조작·중복: **미해결**(4자리 코드·익명 계정으로 참가자 유일성 보장 불가). 단, 웹앱을 성적과 무관한 연습용으로 한정해 실제 피해 가능성은 낮아짐.

## 3. 점수 규칙
불합리 사례: 0/8→0/8 = 10점(목표 달성) / 1/8→3/8 = 20점 / 5/8→5/8 = 10점 / 6/8→4/8 = 0점 / 8/8→7/8 = 20점. 20점이 '성장'과 '숙달'을 동시에 의미.
- 찍기 운: 모두 무작위로 찍을 때 B에서 20점 받을 확률 약 19.1%, B·C 중 한 번 이상 약 30.9% (가정에 따른 계산, 실제는 확실하지 않음)
- 권고안: 20점 = 7/8 이상 또는 기준 +2 이상 → **"숙달 또는 향상"** / 10점 = ±1 → **"유지"** / 0점 = −2 이하 → **"보완 필요"**
- 팀 판정: **15점 이상 "학습목표 달성", 15점 미만 "도전 중"** — 기존 10점 '성장 목표 달성'·15점 '성장 우수' 폐지
- 기준점 보정: "진단이 A보다 25%p 이상 높으면 평균" **폐지 권고**(12문항과 8문항 평균이 더 정확하다는 보장 없음, 소수점 처리 불명확). 진단은 팀 구성·수준 파악에만. A 결석자는 반 평균 대입 대신 **성장 판정 보류**, 최초 응시를 기준으로.
- 참여 촉진 지표로 쓰고 엄밀한 성장 측정이라고 하지 말 것.

## 4. Firebase 보안
보안 규칙은 서버에서 실행되어 상당한 방어 가능. 그러나 익명 로그인은 사람의 유일성을 보장하지 않음. 4자리 코드 추측 취약 → 무작위 8자리 이상 + QR. "교수 화면이 서버 데이터로 재계산"은 서버 채점이 아님(교수 브라우저가 내려받아 채점). 상위 경로 읽기 허용 시 하위에서 막을 수 없음(공식 문서). 정답지·교수 권한을 학생이 받는 자바스크립트에 넣지 말 것. 연습 정답 수집은 막을 수 없음 → 평가 정답을 서버에 넣지 않는 판단 유지.

## 5. 3주·테스트 40개
전체 설계 구현은 확실하지 않음, **기능을 줄인 연습용 웹앱은 현실적**. 유지: 코드 입장, 연습 공통 퀴즈 8문항, 자동 채점·해설 / 축소: CSV 4개→1개 / 삭제: 복수 회차 관리, 교수 점수 대시보드, 앱 팀 점수, 실시간 순위표.
**첫 버전은 데이터베이스 없는 정적 웹앱으로 충분**(결과는 그 기기에만, 공식 평가 미사용). Firebase 저장·교사용 CSV는 다음 버전. 휴대폰 10대 모의 수업은 50명 운영의 근거가 아님.

## 6. 먼저 끝난 사람의 답 유출
전원 종료 후 해설은 필수지만 충분하지 않음. 권장: **문제·보기 순서 섞기**, **평가 시간창 통일(같은 시작·종료 시각)**, 먼저 끝난 사람 대화 금지. Socrative의 문제·보기 섞기, 문항 피드백 끄기, 최종 점수 숨기기, 한 번만 응시 설정 활용. 성적 미반영 성인 수업이므로 완벽 봉쇄보다 해석 한계 인정.

## 7. 트랙 A 추가 제약
