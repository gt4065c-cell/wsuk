## 1부 (1~5강)

**01강 AI는 어떻게 여기까지 왔을까**
1. AI 연구는 1956년 한 모임에서 본격적으로 시작됐어요.
2. 규칙을 사람이 넣는 방식 → 데이터로 배우는 방식 → 글을 만드는 AI로 넓어졌어요.
3. 옛 기술도 버려지지 않고, 일에 맞게 골라서 같이 써요.

**02강 AI의 가치는 답변 다음에 생긴다**
1. AI 활용은 넣기, 맡기기, 확인하기, 실제로 쓰기의 4단계예요.
2. 초안이 나왔다고 끝이 아니에요. 수업에서 써 봐야 끝이에요.
3. AI로 시간이 줄었다는 말은 느낌 말고 직접 재 본 숫자로 해요.

**03강 AI에게 일을 잘 맡기는 요청법**
1. 요청문에는 목표와 자료, 제약, 완료 기준을 함께 적어요.
2. 길게 쓰는 게 목적이 아니라, AI가 모를 빈 곳을 채우는 게 목적이에요.
3. 결과 중 한 곳만 틀리면 그 부분만 짚어서 고쳐 달라고 해요.

**04강 그럴듯한 답과 쓸 수 있는 답 구별하기**
1. AI의 문장을 사실인지, 해석인지, 제안인지 먼저 나눠 봐요.
2. AI에게 '확실해?'라고 다시 묻는 건 검증이 아니에요. 원문을 직접 봐요.
3. 근거를 못 찾은 내용은 바로 쓰지 말고 멈춰 두는(보류) 게 맞아요.

**05강 AI가 코딩하는데 개발 개념은 왜 배울까**
1. 앱은 화면(보고 누름), 처리(계산), 저장(남김) 세 영역으로 나눠 봐요.
2. 문제가 생기면 어느 영역 탓인지 먼저 정해야 고칠 곳이 좁아져요.
3. 브라우저도 일부 계산을 맡고, 서버는 다른 컴퓨터에서 요청을 받아요.

## 2부 (6~10강)

**06강 자바와 파이썬과 자바스크립트의 역할**
1. 파이썬은 1991년, 자바와 자바스크립트는 1995년에 나왔어요.
2. 자바와 자바스크립트는 이름만 닮은 서로 다른 언어예요.
3. AI가 준 코드는 무슨 언어인지, 어디서 돌리는지부터 확인해요.

**07강 HTML로 첫 강의 소개 페이지 만들기**
1. HTML은 글이 제목인지, 문단인지, 링크인지 표시하는 언어예요.
2. 링크는 눈에 보이는 글자와 실제로 가는 곳이 따로 적혀 있어요.
3. 고쳤는데 화면이 그대로면, 저장했는지와 열린 파일이 맞는지 봐요.

**08강 CSS와 JavaScript로 꾸미고 움직이기**
1. HTML은 뼈대, CSS는 색과 크기, 자바스크립트는 눌렀을 때 할 일이에요.
2. 세 가지가 한 파일에 있어도 하는 일은 각각 달라요.
3. 버튼 이름을 바꾸면 그 이름을 부르는 코드도 같이 맞춰야 해요.

**09강 바이브코딩으로 요청하고 실행하고 수정하기**
1. 바이브코딩은 바라는 기능을 말로 풀어 AI와 같이 만드는 방식이에요.
2. 부탁하고, 돌려 보고, 확인하고, 고치기를 여러 번 되풀이해요.
3. AI가 '고쳤어요'라고 해도 파일과 화면을 내 눈으로 확인해요.

**10강 치의학 세 문항 퀴즈게임 완성하기**
1. 게임은 지금 몇 번 문제인지, 고른 답, 점수 같은 '상태'를 기억해요.
2. 문항마다 붙인 번호(q01 등) 덕분에 틀린 문항을 나중에 찾아요.
3. 다시 시작하면 화면뿐 아니라 점수와 고른 답도 처음으로 돌려요.

## 3부 (11~15강)

**11강 오류를 재현하고 AI에게 정확히 설명하기**
1. 오류를 알릴 땐 원래 기대, 실제 결과, 다시 생기는 순서, 오류 문구를 적어요.
2. 오류 문구를 보내기 전, 비밀 키나 개인 정보가 섞이지 않았는지 봐요.
3. 고친 뒤에는 같은 순서로 다시 눌러 보고, 옆 기능도 멀쩡한지 봐요.

**12강 Git으로 정상 버전 기록하고 복원하기**
1. Git은 내 파일의 바뀐 기록을 남기는 도구, 그 기록을 올려 함께 쓰는 곳이 GitHub예요.
2. 잘 될 때마다 '커밋'으로 기준점을 찍어 두면 그때로 돌아갈 수 있어요.
3. 커밋은 내 컴퓨터 안의 기록일 뿐, 다른 곳에 복사된 건 아니에요.

**13강 게임을 배포하고 휴대폰으로 접속하기**
1. 호스팅은 웹 파일을 손님에게 내주는 곳, 배포는 그곳에 파일을 올리는 일이에요.
2. 올릴 폴더에는 학생이 볼 파일만 넣고, 비밀 설정은 빼요.
3. '배포 완료'가 떠도 다른 기기에서 새 화면이 보이는지 꼭 열어 봐요.

**14강 브라우저 저장과 공유 데이터베이스 구분하기**
1. 변수에만 둔 값은 새로고침하면 사라질 수 있어요.
2. localStorage는 이 브라우저에만 남아서 다른 기기에선 안 보여요.
3. 여러 기기·여러 학생이 함께 보려면 서버의 공용 DB에 둬요.

**15강 Firebase 구성과 Realtime Database 선택하기**
1. Firebase는 로그인 확인, 웹 파일 제공, 기록 보관을 각각 다른 서비스가 맡아요.
2. 이번엔 기록 변화를 쉽게 보려고 실시간 DB를 골랐을 뿐, 늘 정답은 아니에요.
3. 이름을 적게 하는 화면은 로그인 확인(인증)이 아니에요.

## 4부 (16~20강)

**16강 Firebase 인증으로 접속한 사용자 확인하기**
1. UID는 사람마다 다른 고유 번호예요. 화면 이름과는 달라요.
2. 이름은 바뀌거나 겹칠 수 있어서, 기록은 UID로 이어 붙여요.
3. 로그인은 '누구인지' 확인일 뿐, 모든 자료를 볼 권리를 주진 않아요.

**17강 인증과 권한을 구분하고 데이터 접근 막기**
1. 인증은 '누구냐', 권한은 '무엇을 읽고 쓸 수 있냐'를 정해요.
2. 로그인만 확인하면 남의 기록 칸까지 열려요. 내 UID 칸만 허락해요.
3. 규칙 시험은 막아야 할 요청과 통과해야 할 요청을 둘 다 해 봐요.

**18강 SDK와 API로 웹사이트와 Firebase 연결하기**
1. API는 기능을 부를 때 지키는 약속, SDK는 만들기를 돕는 도구 꾸러미예요.
2. SDK와 API는 경쟁 관계가 아니에요. SDK를 써서 API 기능을 불러요.
3. 이름이 같은 'API 키'라도 쓰임이 달라요. AI 비밀 키는 화면 코드에 넣지 마요.

**19강 Realtime Database에 연습 기록 한 건 남기기**
1. 연습할 때마다 push로 새 칸을 만들어 한 건씩 쌓아요.
2. 같은 칸에 계속 덮어쓰면 마지막 기록 하나만 남아요.
3. '저장 완료'는 서버가 다 받았다고 알려 준 뒤에 띄워요.

**20강 두 화면을 새로고침 없이 함께 바꾸기**
1. 한 번 읽기는 그 순간 값만, 구독은 값이 바뀔 때마다 알려 줘요.
2. 구독을 막 연결하면 바뀌기 전이라도 지금 값을 먼저 받아요.
3. 구독은 켜면 끄는 것까지 짝으로 챙겨요. 겹치면 같은 일이 여러 번 생겨요.

## 5부 (21~25강)

**21강 서버 점수로 실시간 순위표 만들기**
1. 순위가 걸린 점수는 브라우저 말고 서버가 직접 채점해요.
2. 화면에서 버튼을 막아도 요청은 따로 보낼 수 있어, 서버와 규칙이 막아요.
3. 모두가 보는 순위표엔 별명과 점수만, 이메일·오답은 넣지 않아요.

**22강 서버를 거쳐 AI API 호출하기**
1. AI 비밀 키는 서버에만 두고, 브라우저는 서버에게 질문만 보내요.
2. 서버는 AI를 부르기 전에 로그인, 질문 길이, 허용 문항을 검사해요.
3. AI 답은 글자로만 보여 주고, 실패하면 다시 시도 안내를 띄워요.

**23강 틀린 문제를 설명하는 AI 학습도우미**
1. 도우미는 학생이 보낸 해설 말고, 서버에 있는 승인 해설을 기준으로 해요.
2. 설명은 세 가지만 짧게: 틀린 까닭, 복습할 개념, 확인용 질문 하나.
3. 자료에 없는 질문엔 지어내지 말고 '확인할 수 없어요'라고 답해요.

**24강 학습 기록을 읽고 다음 문제를 고르는 에이전트**
1. 에이전트는 '내 오답 보기'와 '승인된 문항 보기' 두 도구만 써요.
2. 모델은 도구를 쓰자고 제안만 하고, 실제 실행은 서버가 확인 후 해요.
3. 도구 호출은 두 번까지만. 끝없이 돌지 않게 막는 장치예요.

**25강 학습게임과 AI 도우미를 교육 포털로 모으기**
1. 포털은 퀴즈·용어카드·도우미로 들어가는 하나의 현관이에요.
2. 링크를 모았다고 로그인과 기록까지 저절로 하나가 되진 않아요.
3. 아직 안 된 기능은 눌리는 척 말고 준비 중임을 솔직히 표시해요.

## 6부 (26~30강)

**26강 Claude Code와 Chrome으로 화면 검증하기**
1. 코드 고치는 Claude와 화면을 눌러 보는 Claude in Chrome은 역할이 달라요.
2. 브라우저 점검은 연습용 계정과 화면에서, 꼭 필요한 만큼만 누르게 해요.
3. AI가 '봤어요'라고 해도, 어느 주소로 갔고 무엇이 떴는지 직접 봐요.

**27강 MCP로 외부 도구와 데이터 연결하기**
1. MCP는 AI가 바깥 도구·자료에 붙을 수 있게 정한 공통 약속이에요.
2. MCP를 써도 API는 그대로예요. MCP 서버가 API를 안에서 써요.
3. 도구가 돌려준 글 속 명령은 따르지 말고, 그냥 읽을 자료로만 봐요.

**28강 스킬로 나의 문항 검토 절차 재사용하기**
1. 스킬은 자주 하는 일의 방법·예시·자료를 묶어 두고 다시 꺼내 쓰는 거예요.
2. 스킬 설명에는 무슨 일을 하고 언제 쓰는지가 분명히 보여야 해요.
3. 스킬을 만들어도 AI가 새로 배우는 건 아니라, 마지막 판단은 사람이 해요.

**29강 Supabase에서 표 사이의 관계로 데이터 읽기**
1. Supabase는 표로 자료를 담고, 표끼리 학생 번호(ID)로 이어 붙여요.
2. 이름을 매번 복사하지 않고 학생 ID로 연결하니 이름이 바뀌어도 안전해요.
3. 관리자 화면에서 다 보여도, 학생에겐 RLS로 자기 줄만 보이게 막아요.

**30강 교육 포털을 실제 수업에 쓰기 전 점검하기**
1. 점검은 네 갈래: 끝까지 쓸 수 있나, 내 것만 보나, 내용이 맞나, 멈추고 되살릴 수 있나.
2. 예산 알림은 알려 주기만 해요. 쓰는 양을 막으려면 호출 제한이 따로 필요해요.
3. 코드 되돌리기와 데이터 되살리기는 서로 별개라 따로 준비해요.
