학습 목표 화면과 처리와 저장의 역할을 구분하여 수정 요청을 한다.

촬영 준비 로컬 퀴즈, 서버 채점과 DB가 연결된 완성본의 별도 녹화. 두
환경을 화면에 표시한다.

## 0:00–0:20 완성 장면

화면 점수 버튼과 새로고침 전후 화면을 보여준다.

버튼은 잘 눌리는데 새로고침하면 점수가 사라집니다. AI에게 게임이
이상하다고만 말하면 어디부터 고칠까요? 개발 개념을 조금 알면 문제의
위치를 설명할 수 있습니다. 오늘은 세 영역만 구분하겠습니다.

## 0:20–1:10 핵심 개념

화면 화면, 처리, 저장을 연결한 간단한 그림을 보여준다.

화면은 사용자가 보고 누르는 부분입니다. 처리는 답을 비교하거나 점수를
계산하는 일이고, 저장은 다음에도 쓸 데이터를 남기는 일입니다. 웹에서는
브라우저가 화면을 표시하고 일부 처리도 맡습니다. 서버는 다른 컴퓨터에서
요청을 받아 처리하는 역할을 합니다. 데이터베이스는 여러 사용자의 기록을
관리할 수 있죠. 프런트엔드와 백엔드라는 말을 만나면 사용자 쪽과 서버 쪽
역할을 먼저 떠올리세요. 모든 처리가 반드시 서버에서만 일어나는 것은
아닙니다.

## 1:10–1:50 화면 실습 1

화면 버튼 크기만 바꾸는 요청을 입력하고 모바일 미리보기를 연다.

첫 번째 문제는 휴대폰에서 선택지가 너무 작은 경우입니다. 이때는 화면을
고쳐야 합니다. 점수 계산이나 저장 방식까지 바꿀 이유가 없죠. 선택지
버튼의 높이와 글자 크기만 조정해 달라고 요청하겠습니다. 바뀐 뒤 같은
문제를 눌러 봅니다. 모양이 개선됐고 정답 처리도 그대로라면 수정 범위를
잘 지킨 겁니다.

## 1:50–2:30 화면 실습 2

화면 정답을 눌렀는데 점수가 오르지 않는 오류를 시연한다.

두 번째는 정답을 골랐는데 점수가 오르지 않는 상황입니다. 버튼 색을
바꾸는 것으로 해결되지 않습니다. 선택한 답과 정답을 비교하는 처리 흐름을
봐야 하죠. 어떤 문항에서 어떤 답을 눌렀는지, 기대 점수와 실제 점수가
무엇인지 전달합니다. 문제를 구체적으로 설명할수록 AI가 확인할 범위도
줄어듭니다.

## 2:30–3:10 화면 실습 3

화면 점수를 올린 뒤 새로고침하고 기록이 사라지는 모습을 보여준다.

세 번째는 점수가 화면에만 있다가 사라지는 경우입니다. 지금 프로그램은
현재 브라우저의 임시 상태로 점수를 들고 있습니다. 다른 기기에서도 보려면
공유 저장소가 필요합니다. 같은 기기에서만 유지하면 되는지, 여러 학생이
함께 볼 것인지 먼저 결정해야 합니다. 저장이라는 말 안에도 서로 다른
요구가 있다는 점을 기억하세요.

## 3:10–3:50 화면 실습 4

화면 완성본 녹화로 전환해 브라우저 요청과 서버 처리와 DB 기록을 짚는다.

이제 뒤에서 만들 완성본을 잠깐 보겠습니다. 학생이 답을 제출하면 서버가
채점하고 데이터베이스에 결과를 남깁니다. 브라우저는 그 결과를 받아
보여주죠. 화면에서 점수 숫자를 바꾼다고 공식 기록까지 바뀌어서는 안
됩니다. 공정한 순위가 필요할 때는 믿을 수 있는 위치에서 채점해야 한다는
뜻입니다. 상세 구현은 게임 연결 강의에서 다룹니다.

## 3:50–4:30 작동 확인

화면 버튼이 작다, 채점이 틀리다, 기록이 없다 세 사례를 분류한다.

버튼이 작으면 화면, 정답 비교가 틀리면 처리, 다음 접속에서 기록을 찾지
못하면 저장을 먼저 살펴봅니다. 실제 오류는 여러 영역에 걸칠 수도 있지만
출발점을 잡는 데 도움이 됩니다. 개발 개념을 배우는 목적은 모든 코드를
직접 쓰는 데 있지 않습니다. 요청과 검증을 더 정확하게 하는 데 있습니다.

## 4:30–5:00 오늘의 미션

화면 세 줄 요구사항 미션을 표시한다.

만들고 싶은 도구를 화면, 처리, 저장 세 줄로 적어 보세요. 예를 들어
문제를 보여주고, 답을 채점하고, 응시 기록을 남긴다고 쓰면 됩니다. 다음
시간에는 이 일을 구현하는 언어들이 어떤 역할을 맡는지 살펴보겠습니다.

## 실습 요청문과 성공 기준

요청문 내 퀴즈 요구사항을 화면, 처리, 저장으로 구분해 줘. 각 기능이
브라우저에서 처리돼도 되는지 서버 검증이 필요한지 이유를 짧게 설명하고
아직 구현하지 마.

성공 기준 세 가지 문제 상황에서 먼저 확인할 영역과 수정 범위를 말할 수
있다.

# 06강 자바와 파이썬과 자바스크립트의 역할

## 0:00–0:20 완성 장면

화면 같은 평균 점수를 계산하는 서로 다른 언어 예시를 보여준다.

같은 점수 계산도 여러 언어로 표현할 수 있습니다. 왜 언어가 이렇게

## 0:20–1:10 핵심 개념

화면 세 언어의 연도와 주요 쓰임을 표시한다.

파이썬은 읽기 쉬운 표현과 생산성을 중시하며 발전했고 1991년에
공개됐습니다. 자바는 여러 환경에서 실행할 수 있는 이식성을 중요한 목표로
삼아 1995년에 공개됐죠. 자바스크립트도 1995년에 등장했지만 웹페이지의
동작을 만드는 별개의 언어입니다. 지금은 각 언어의 활용 범위가 넓어서
하나의 용도로만 묶을 수는 없습니다. 이 과정에서는 브라우저에서 동작하는
게임을 만들기 위해 자바스크립트를 사용합니다. 언어 선택은 목적과 실행
환경을 함께 보고 결정합니다.

오늘은 사용자 화면의 동작에 집중하겠습니다. 자바를 설치해야 이 버튼이
작동하는 것은 아닙니다.

## 1:50–2:30 화면 실습 2

계산을 자동화할 때 이런 방식이 도움이 됩니다. 실제 분석에서는 결측값과
자료 형식도 확인해야겠죠. 지금은 숫자 다섯 개로 언어가 데이터를 처리하는
모습을 보는 데 집중합니다.

어디에서 실행하는지 확인해 보세요.

## 0:00–0:20 완성 장면

## 0:20–1:10 핵심 개념

화면 h1, p, a 태그와 화면의 대응 부분을 강조한다.

HTML은 문서의 구조와 의미를 표시하는 마크업 언어입니다. 제목인지
문단인지 링크인지를 태그로 나타내죠. 브라우저는 파일을 읽고 그 구조에
맞게 화면을 보여줍니다. 제목에는 h1, 문단에는 p, 연결에는 a 같은 요소를
사용합니다. 태그를 모두 암기할 필요는 없습니다. 화면의 어떤 부분을
바꾸려면 파일의 어디를 수정하는지 연결해서 보는 것이 먼저입니다. 오늘
파일에는 디자인과 복잡한 동작을 최소한으로 넣었습니다.

것은 아닙니다. 인터넷에 올리는 배포는 뒤에서 다룹니다. 오늘은 파일을
바꾸고 결과를 확인하는 데 집중하겠습니다.

합니다. 순위 점수를 직접 바꾸는 요청도 막혀야 하죠. 관리자 메뉴가 숨겨져
있다는 것만 확인하지 않습니다. 서버 요청 자체가 거부되는지 봅니다. 실제
학생 정보로 시험하지 않고 가상 계정과 기록을 사용합니다. 공개 순위에는
꼭 필요한 별칭과 점수만 표시하겠습니다.

# 촬영 준비와 공통 데이터 설계

30강 전체에서 같은 시험 프로젝트와 문항 ID를 유지합니다. 아래 항목은

## 실습 자료 준비

1~5강 교수자가 작성한 짧은 강의 메모, 검토된 문항, 가상 응답, 검증
연습용 오류 초안을 준비합니다.

6~12강 단일 HTML 파일에서 시작합니다. 문항은 q01~q03, 점수는 0~3으로
맞춥니다. 정상본과 의도적 오류본을 나누고 Git은 별도 연습 폴더에서
사용합니다.

13~20강 하나의 Firebase 시험 프로젝트에 Hosting, Google 인증, Realtime
Database를 설정합니다. 로컬 파일 직접 열기는 7강의 단일 파일 체험에만
사용하고 SDK 실습은 웹 서버 주소에서 진행합니다.

21~24강 채점 서버, AI 호출 함수, 도구 실행기는 사전 제작이 필요합니다.
구현 전체를 5분에 끝낸다고 설명하지 않습니다. 실제 실행을 녹화하며 실패
장면은 시험 모드임을 표시합니다.

25~30강 포털의 실제 링크, 공식 Chrome 연동, 읽기 전용 MCP, 문항 검토
스킬, 가상 Supabase 표를 준비합니다. 설치와 결제 및 권한 설정은 본 촬영
전에 마칩니다.

## 데이터와 서버의 공통 약속

개인 연습 practice/{uid}/{attemptId}에 문항 ID, 선택 답, 연습 점수, 서버
시각을 기록합니다. 본인 접근만 허용하며 공식 순위 점수로 신뢰하지
않습니다.

공식 순위 leaderboard/{sessionId}/{uid}에는 공개 별칭과 서버 채점 점수만
둡니다. 참가자에게 필요한 읽기만 허용하고 클라이언트 쓰기는 차단합니다.

채점 서버 submitAttempt는 인증 UID, 응시 ID, 문항 ID와 답을 검증합니다.
서버 정답표를 사용하고 중복 집계와 재전송을 처리합니다. 한 수업 한 번
응시 규칙을 명시합니다.

AI 서버 askTutor와 explainWrongAnswer는 비밀 키를 서버에 보관합니다.
승인 문항 조회, 인증, 입력 검증, 시간 제한과 사용자별 호출 제한을
적용합니다.

에이전트 getMyMistakes와 getApprovedQuestion만 허용합니다. 서버가 UID를
강제하고 도구 호출은 최대 2회로 제한하며 결과 문항 ID를 다시 검증합니다.
