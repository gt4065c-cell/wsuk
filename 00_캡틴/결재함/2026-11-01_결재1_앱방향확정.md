## 한 줄 요약
**ChatGPT의 반대 의견을 받아들여 추천안을 바꿨습니다. 이번 학기 수업은 검증된 무료 도구(Socrative) + 스프레드시트 향상점수로 운영하고, 우리 웹앱은 기능 4개짜리로 작게 만들어 수업과 분리해 시험하는 "투 트랙" 안을 추천합니다.**

> 이번 맛보기의 사용자는 대학생이 아니라 캡틴 수업의 **교수자·교육 실무자(성인)**입니다. 결과는 대학생 앱을 위한 "첫 실험"으로 해석합니다.
> 이번 학기의 성공 기준: "6주 만에 앱을 완성했나"가 아니라 **"성인 학습자에게 공정하고 부담이 적은 팀 학습 방식의 가능성을 확인했나"**.

## 왜 추천안을 바꿨나요? (ChatGPT가 찾은 우리 설계의 구멍)
1. **수준별 문제와 향상점수가 서로 부딪힙니다.** 쉬운 문제를 받은 사람은 정답률이 오르고, 어려운 문제를 받은 사람은 떨어집니다. 그러면 실제로 더 많이 배운 사람이 오히려 점수를 잃습니다. → 비서실장도 동의합니다. 우리 설계의 가장 큰 결함이었습니다.
   **해결: 연습은 수준별, 향상점수는 모두 같은 "공통 평가 문항"으로 계산.**
2. **진단 3~5문항은 너무 적습니다.** 한 문제만 틀려도 등급이 바뀝니다. → 진단 10~12문항, 결과는 팀 구성 참고용으로만.
3. **기능 6개를 6주 안에 동시에 안정적으로 만드는 것은 무리입니다.** → 자동 난이도 조절은 겨울방학으로 미루고, 웹앱은 4개 기능만.

## 핵심 내용 3가지 (근거)
1. **빈자리는 여전히 있습니다**: 조사한 수업용 실시간 퀴즈 도구 8개(대부분 초중고용) 중에는 실력 차이를 보정해 겨루는 기능이 없었습니다. 다만 이번 학기에는 앱으로 증명하기보다 **"성장 기준 팀 경쟁이 성인에게 통하는가"라는 가설**을 먼저 확인합니다.
2. **연구 근거**: 퀴즈로 떠올리기 + 바로 해설은 효과가 분명합니다. 연습 퀴즈는 평균적으로 시험불안을 낮춥니다(Yang 외 2023, Educational Psychology Review — 사실검증 확인). 위험은 퀴즈 자체가 아니라 **"동료 앞에서 평가받는 방식"**입니다 → 개인 점수 비공개, 첫 회차는 팀 대결 없음.
3. **문제는 준비됐습니다**: 1~15강 54문항. 다만 ChatGPT 지적대로 **연습용과 평가용을 나누고**, 진단 문항을 10~12개로 늘려야 합니다.

## 캡틴이 결정할 것

### ① 이번 학기 방향
- [ ] **수정 추천: 투 트랙 (기존 도구로 수업 + 웹앱은 분리해 검증)**
  - 트랙 A (수업): Socrative(무료 50명)로 퀴즈, 향상점수·팀 순위는 스프레드시트로 계산
  - 트랙 B (개발): 우리 웹앱을 **별명 입장 · 공통 퀴즈 · 자동 채점 · 결과 저장** 4개 기능만 만들어 모의 테스트 → 안전이 확인되면 마지막 회차에 수업에서 시연 ("이 앱도 강의에서 배운 방법으로 만들었습니다")
  - 자동 난이도 조절·실시간 순위표는 **겨울방학**으로
- [ ] 처음 추천했던 1안: 기능 6개를 직접 만들어 수업에 바로 사용 — ChatGPT·비서실장 모두 이번 학기에는 **비추천**으로 의견 변경
- [ ] 기존 도구만 사용, 이번 학기 개발 없음 — 가장 안전하지만 "수업의 완성 예시"를 보여 줄 수 없음

### ② 대결 방식
- [ ] **추천: 이름은 "AI Agent 실무역량 팀 챌린지"** — 첫 회차는 팀 대결 없이 개인 연습 + 익명 반 전체 결과만 → 2회차부터 교수님이 직접 짠 혼합 수준 3~4인 팀, 팀 점수 = 팀원 향상점수 **평균**, 팀 순위는 활동 끝난 뒤에만 공개, 목표를 넘은 팀은 모두 인정, 원하지 않는 분은 비경쟁 참여 가능, 속도 보너스 없음
- [ ] 팀끼리 경쟁 없이 반 전체 협동 목표만

### ③ 성적 반영
- [ ] **반영하지 않음 (추천)** — 퀴즈는 개념 이해·참여의 보조지표로만, 실무 역량은 과제·결과물로 평가
- [ ] 참여 여부만 반영 (점수 무관)

## 6주 일정 (투 트랙 승인 시)
| 주 | 트랙 A (수업) | 트랙 B (웹앱) |
|---|---|---|
| 1주 | 문항 검수·연습/평가 분리, Socrative 계정 테스트 | 설계 (→ 🔴결재2) |
| 2주 | 5~10명 예비 실험 (스프레드시트 향상점수) | 4개 기능 제작 |
| 3~4주 | 1회차(개인 연습) → 2회차(팀 챌린지) | 중복 접속·새로고침·재접속 테스트 |
| 5주 | 3회차 + 익명 설문 | 모의 수업 동시 접속 테스트 (→ 🔴결재3) |
| 6주 | 결과 분석·보고 | 안전 확인되면 수업에서 시연 |

## 전략기획실장(ChatGPT) 교차검토 의견
- **동의하는 점**: 6주 안에 작동하는 시제품은 만들 수 있음, 퀴즈+해설의 효과, 성적 미반영, 혼합 수준 팀
- **반대·우려하는 점**: ① 수준별 난이도와 향상점수 충돌(가장 심각) ② 진단 문항 부족 ③ 기능 과다 ④ 성인 교수자의 체면 부담(위험 중간~높음) ⑤ 놓친 위험: 진단 일부러 못 보기, 별명으로도 신원 짐작 가능, 점수 조작·중복 접속, 객관식이 실무 역량을 못 잼, 재미≠학습 효과
- **비서실장의 최종 판단**: ①은 우리 설계의 진짜 결함이라 **전면 수용**했습니다. ②③④⑤도 대부분 수용했습니다. 다만 "웹앱 개발을 이번 학기에 미루자"는 부분은 받아들이지 않았습니다. 이 과목은 수강생이 AI로 앱을 만드는 수업이라 웹앱 자체가 교재가 되기 때문입니다. 그래서 **수업과 분리한 트랙 B**로 개발을 계속합니다.
- ⚠️ ChatGPT 답변 속 수치(Firebase 무료 한도, Blooket 보고서 유료 여부, 2023·2024 연구)는 **아직 검증 전**입니다. 결재2 전에 사실검증관이 확인합니다.
