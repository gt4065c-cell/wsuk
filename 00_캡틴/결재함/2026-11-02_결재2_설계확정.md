## 한 줄 요약
**수업(트랙 A)은 3회차 "팀 챌린지"를 Socrative + 자동 계산 엑셀로 바로 시작할 수 있게 준비됐고, 웹앱(트랙 B)은 강의와 같은 Firebase로 4개 기능만 11/2~11/22(설계 포함 약 3주) 안에 만드는 설계를 승인받고자 합니다.**

## 핵심 내용 3가지
1. **문제 은행 67문항, 겹치지 않게 나눔**: 진단 12 / 공통 평가 A·B·C 각 8(난이도·강의 범위를 똑같이 맞춘 쌍둥이 세트) / 연습 31. 세트마다 정답 위치(1~4번)가 고르게 퍼지도록 비서실장이 보기 순서를 정리했습니다.
2. **점수 규칙은 "운으로 바뀌지 않게"**: 출발점(평가 A)보다 2문제 이상 더 맞히면 20점, 한 문제 차이는 10점(유지), 2문제 이상 덜 맞히면 0점, 7문제 이상 맞히면 늘 20점. 팀 점수 = 팀원 평균, 10점 "성장 목표 달성" · 15점 "성장 우수". 엑셀은 이 규칙으로 195개 항목을 파이썬으로 따로 계산해 대조 — 모두 일치(기록: `05_성장팀/2026-11-01_팀챌린지_설문과합격기준.md` '엑셀 검증 기록'). *(문제 수 설명은 출발점이 평가 A일 때의 예시이고, 실제 규칙은 ±20%p)*
3. **웹앱은 "누락 0, 중복 0, 채점 100% 일치"를 최우선**: 정답은 답을 확정하기 전에는 휴대폰에 보내지 않고, 공식 점수는 서버에 저장된 답으로 다시 계산합니다. 테스트 항목 40개, 실제 휴대폰 10대 이상 모의 수업을 통과해야 결재3에 올립니다.

## 캡틴이 결정할 것

### ① 웹앱 도구
- [ ] **Firebase (추천)** — 강의 15~21강에서 수강생이 쓰는 도구와 같아서 앱이 곧 교재. 잠들지 않음. 주의: 같은 와이파이에서 새 계정 1시간 100개 제한 → 계정 재사용, 50명 자동 시험은 가짜 서버(에뮬레이터)에서만, 시연 1주 전 한도 상향 신청
- [ ] Supabase — 서버 채점은 더 쉽지만 **1주일 안 쓰면 자동 일시정지**, 강의에선 29강에서만 다룸

### ② 문제 푸는 속도
- [ ] **각자 자기 속도로 (추천)** — 속도 경쟁 없음, 늦게 온 분도 1번부터
- [ ] 교수님이 한 문항씩 넘기기

### ③ 정답·해설 보여 주는 때 — ⚠️ 비서실장이 서비스 기획자 추천을 수정
- [ ] **연습만 답하자마자, 진단·평가는 반 전체가 끝난 뒤 (비서실장 추천)** — 각자 속도로 풀면 먼저 끝난 분이 옆 사람에게 정답을 알려 줄 수 있어, 기준점수·향상점수·팀 편성이 흔들립니다. 늘어나는 일: 보안 규칙 1줄 + 종료 후 해설 화면 + 테스트 2개(T-39·T-40) → 설계서 v0.2에 반영 완료.
- [ ] 모든 세트에서 답하자마자 (서비스 기획자 원안) — 가장 간단하지만 정답 유출 위험
- (트랙 A Socrative도 같은 원칙: 진단·평가는 "즉시 피드백"과 "보기 섞기"를 끄고 진행)

### ④ 참가자 코드 나눠 주기
- [ ] **섞은 종이 카드 무작위 배부 (추천)** — 교수님도 누가 어떤 코드인지 모름, 학기 내내 같은 카드
- [ ] 명단과 코드를 짝지어 교수님이 보관 — 분실 복구는 쉽지만 "실명 없음" 원칙 약화

### ⑤ 평가 문항 최종 검토 (교수님만 하실 수 있는 일)
- [ ] **(추천) 수업 전에 평가 A·B·C 24문항 + 진단 12문항을 훑어보기** — 점수 계산에 쓰이는 문항이라 교수님 확인이 필요합니다. 비서실장이 한 화면에 보기 좋게 정리해 드리겠습니다(약 15분).
- [ ] 초안 그대로 사용 — **비추천**: 점수에 쓰이는 문항이고, 설계서 규칙상 검토 안 된 문항은 모의 테스트에만 씁니다

## 알려 드릴 위험과 미확인 사항
- 1회차가 23문항이라 20분이 빠듯할 수 있음 → 예비 실험에서 시간 재고, 모자라면 마무리 해설을 2회차 앞으로
- Socrative 무료: 저장 퀴즈 5개·방 1개 → 퀴즈 7개를 돌려 올림(1·2회차 5개 먼저, 1회차 뒤 지우고 3회차 퀴즈 교체). **지워도 보고서가 남는지는 미확인** → 지우기 전 엑셀 내려받기 필수, 예비 실험에서 확인
- 무료 한도 수치는 공식 페이지 발췌로 확인했지만, 설정할 때 관리 화면에서 한 번 더 확인 필요
- 설문은 `05_성장팀/…설문과합격기준.md` 하나를 기준으로 통일(공정성 문항 Q6 포함)
- 참가자 코드: **4자리 종이 카드 한 장**을 수업(Socrative)과 웹앱에서 같이 씀 → 두 트랙의 기록이 같은 코드로 연결
- 웹앱이 결재3을 통과해도 **3회차 공식 평가는 Socrative**로 하고, 웹앱은 점수에 쓰지 않는 연습 세트로만 시연(1회차 기준점수와 섞이지 않게)
  - 그래서 웹앱 서버에는 **연습 31문항만** 올리고 진단·평가 문항은 올리지 않습니다(유출 위험 0). '종료 뒤 해설' 기능은 시험용 가짜 평가 세트로 테스트합니다.
- 점수에 쓰이는 36문항(진단 12 + 평가 24)은 아직 '초안' → ⑤번 교수 검토 필요
- 엑셀 파일 이름에 날짜가 없음(사칙 5장) — 여러 문서가 이 이름을 가리키고 있어 이번엔 그대로 둠
