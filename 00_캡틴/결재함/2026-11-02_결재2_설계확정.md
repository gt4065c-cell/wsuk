## 한 줄 요약
**수업(트랙 A)은 3회차 "팀 챌린지"를 Socrative + 자동 계산 엑셀로 바로 시작할 수 있게 준비됐고, 웹앱(트랙 B)은 강의와 같은 Firebase로 4개 기능만 3주(11/5~11/22) 안에 만드는 설계를 승인받고자 합니다.**

## 핵심 내용 3가지
1. **문제 은행 67문항, 겹치지 않게 나눔**: 진단 12 / 공통 평가 A·B·C 각 8(난이도·강의 범위를 똑같이 맞춘 쌍둥이 세트) / 연습 31. 세트마다 정답 위치(1~4번)가 고르게 퍼지도록 비서실장이 보기 순서를 정리했습니다.
2. **점수 규칙은 "운으로 바뀌지 않게"**: 출발점(평가 A)보다 2문제 이상 더 맞히면 20점, 한 문제 차이는 10점(유지), 2문제 이상 덜 맞히면 0점, 7문제 이상 맞히면 늘 20점. 팀 점수 = 팀원 평균, 10점 "성장 목표 달성" · 15점 "성장 우수". 엑셀은 이 규칙으로 195개 항목을 따로 계산해 대조 — 모두 일치.
3. **웹앱은 "누락 0, 중복 0, 채점 100% 일치"를 최우선**: 정답은 답을 확정하기 전에는 휴대폰에 보내지 않고, 공식 점수는 서버에 저장된 답으로 다시 계산합니다. 테스트 항목 38개, 실제 휴대폰 10대 이상 모의 수업을 통과해야 결재3에 올립니다.

## 수업 진행 (트랙 A — 결재 후 바로 시작 가능)
| 회차 | 하는 일 | 공개 |
|---|---|---|
| 1회차 | 연습 3 → 진단 12 → 평가 A 8 (팀 대결 없음, 평가 A = 각자의 출발점) | 반 전체 익명 결과만 |
| 2회차 | 팀 연습 → 평가 B | 팀 순위는 활동 후 |
| 3회차 | 팀 연습 → 평가 C → 함께 인정 → 1분 익명 설문 | 활동 후 |
- 입장: Socrative 링크(https://api.socrative.com/rc/gFMdwf) → 이름 칸에 참가자 코드

## 캡틴이 결정할 것

### ① 웹앱 도구
- [ ] **Firebase (추천)** — 강의 15~21강에서 수강생이 쓰는 도구와 같아서 앱이 곧 교재. 잠들지 않음. 주의: 같은 와이파이에서 새 계정 1시간 100개 제한 → 계정 재사용, 50명 자동 시험은 가짜 서버(에뮬레이터)에서만, 시연 1주 전 한도 상향 신청
- [ ] Supabase — 서버 채점은 더 쉽지만 **1주일 안 쓰면 자동 일시정지**, 강의에선 29강에서만 다룸

### ② 문제 푸는 속도
- [ ] **각자 자기 속도로 (추천)** — 속도 경쟁 없음, 늦게 온 분도 1번부터
- [ ] 교수님이 한 문항씩 넘기기

### ③ 정답·해설 보여 주는 때 — ⚠️ 비서실장이 서비스 기획자 추천을 수정
- [ ] **연습·진단은 답하자마자, 평가는 반 전체가 끝난 뒤 (비서실장 추천)** — 각자 속도로 풀면 먼저 끝난 분이 옆 사람에게 평가 정답을 알려 줄 수 있어 향상점수가 흔들립니다. 만들 것이 조금 늘어납니다(세트 종류별 설정 1개).
- [ ] 모든 세트에서 답하자마자 (서비스 기획자 원안) — 가장 간단하지만 평가 정답 유출 위험
- (트랙 A Socrative도 같은 원칙: 평가 세트는 "즉시 피드백" 끄고 진행)

### ④ 참가자 코드 나눠 주기
- [ ] **섞은 종이 카드 무작위 배부 (추천)** — 교수님도 누가 어떤 코드인지 모름, 학기 내내 같은 카드
- [ ] 명단과 코드를 짝지어 교수님이 보관 — 분실 복구는 쉽지만 "실명 없음" 원칙 약화

### ⑤ 평가 문항 최종 검토 (교수님만 하실 수 있는 일)
- [ ] **(추천) 수업 전에 평가 A·B·C 24문항 + 진단 12문항을 훑어보기** — 점수 계산에 쓰이는 문항이라 교수님 확인이 필요합니다. 비서실장이 한 화면에 보기 좋게 정리해 드리겠습니다(약 15분).
